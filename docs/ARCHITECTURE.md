# 架构说明（ARCHITECTURE）

- 状态：Round 01 垂直切片已落地；正式数据管线仍按后续轮次实现。
- 关联：`docs/ADR.md`（技术选型依据）、`docs/DATA-GUIDE.md`（数据面细节）

---

## 1. 分层总览

```
┌─────────────────────────────────────────────┐
│ index.html / src/main.ts / src/style.css     │  入口与外壳（Round 01）
├─────────────────────────────────────────────┤
│ src/game/     游戏胶水层                      │  Phaser 场景、UI 装配；
│               （认识 Phaser，不认识设定）       │  把引擎服务接到画面上
├─────────────────────────────────────────────┤
│ src/engine/   引擎运行时                      │  循环、状态、加载、校验、
│               （不认识 Phaser 之外的具体内容）  │  存档、系统（时间/战斗/图谱）
├─────────────────────────────────────────────┤
│ data/schema/  JSON Schema（数据契约）          │
│ data/base/    基础世界数据（十族，全 JSON）     │  ← 内容唯一来源
│ mods/         mod 覆盖层（同名文件优先）        │
└─────────────────────────────────────────────┘
```

**引擎/数据分离的铁律**：

- `src/engine/` 与 `src/game/` 中**不得出现具体设定文本**（角色名、地名、台词、剧情数值等）；引擎只认协议（schema 定义的形状）。
- 一切世界内容经 `data/` 进入；改世界 = 改 JSON，不动代码。
- 校验内容：`data/schema/` 中的 JSON Schema 是引擎与资料作者之间的契约。

## 2. 启动流程与缺失数据的降级策略

Round 01 已实现地图加载切片：Vite 将 `data/` 作为静态目录服务，场景请求 `/base/maps/round-01-grid.json`（部署使用 `BASE_URL` 前缀）。地图文件随生产构建复制到输出目录。缺失/HTTP 错误、JSON 无法解析或结构检查失败时，场景保留画布并显示可读错误面板。当前结构检查只覆盖网格地图所需字段，不等同于正式 Schema 管线。

Round 02 接入正式资料管线后，启动顺序为：加载配置 → 按 manifest 读取 `data/base/` 十族 → 应用 `mods/` 同名文件覆盖 → Ajv 校验 → 构建游戏状态 → 进入场景。

缺数据/坏数据的行为按严重度分级：

| 情况 | 行为 | 用户所见 |
|---|---|---|
| Round 01 地图请求缺失或失败 | 保留场景并显示错误信息 | 地图路径、HTTP 状态或请求错误及修复提示 |
| 正式加载器中的某数据族目录为空/缺失（如暂无 `quests/`） | **空世界降级**：该族视为空集，游戏照常启动 | 屏幕呈现可读提示（如"当前世界未提供任务数据"），不白屏、不抛栈 |
| Round 01 地图 JSON 语法/结构错误 | 地图不进入场景 | 显示解析原因或逐项结构错误 |
| 正式加载器中的 JSON 语法错误 | 该文件拒绝加载，其余照常 | 可读错误条目：文件路径 + 行列号 + 原因，并列出"跳过的文件清单" |
| 正式 Schema 校验失败 | 同上（按文件拒绝，不整族瘫痪） | 可读错误：文件 + 违反的 schema 规则路径 |
| 关键单点数据缺失（如出生点地图） | 启动失败 | 单一明确错误信息（缺什么、在哪个文件补） |

原则：**宁可小而完整地跑起来，并把问题说清楚；绝不让玩家面对白屏或裸异常。**

## 3. JSON Schema 校验（Ajv，Round 02 接入）

- 每个数据族一个 schema：`data/schema/<族名>.schema.json`（草案 draft-07 或 2020-12，接入时在 ADR-0004 之下注明）。
- 校验发生在**加载期**（开发与生产一致），不在游戏循环内反复校验。
- 校验器为 Ajv 8.x（版本冻结见 `docs/ADR.md`）。
- 错误输出为结构化清单（文件、schema 路径、消息），供屏显与后续测试断言共用。

## 4. mod 覆盖：同名文件优先级（Round 02 提供基础能力，Round 35 增强作者工具）

规则（数据面细节见 `docs/DATA-GUIDE.md` §5）：

1. **路径即身份**：`mods/<modId>/<与 data/base/ 相同的相对路径>` 覆盖基础数据中同名文件，整文件替换、不做字段级合并（合并语义复杂，明确不做）。
2. **优先级**：`mods/` > `data/base/`；多个 mod 同时启用时，按 mod 加载清单的**声明顺序**应用，后者覆盖前者。
3. 覆盖后的数据仍必须通过同一 schema 校验——mod 不能绕过契约。
4. 覆盖关系在启动时可追溯（哪个文件被哪个 mod 覆盖），便于排查。

## 5. 热重载（后续功能，Round 36 规划）

- 目标：开发模式下修改 `data/` JSON 后，游戏在不重启的情况下刷新受影响数据。
- 实现路径：Vite 开发服务器的模块/资源更新事件 + 引擎侧"数据族重载"接口；生产构建不含热重载。
- 状态：仅规划，未实现，不引入任何相关依赖。

## 6. 代码组织约定

- `src/engine/` 内模块不 import `src/game/`（单向依赖：game → engine）。
- 引擎对外暴露 TypeScript 接口（协议优先），数据形状由 schema 与接口共同约束。
- 每个 Round 的实现变更记录于 `DEVLOG.md`，架构级变更必须先补 ADR。
