# 擂台挑战设计（Round 20）

## 玩家流程

1. 站在带金色“擂”字标记的入口格或其四向相邻格按 E，查看赛事说明、赛程、彩头和历史战绩。
2. 首次夺魁彩头尚未领取时，确认背包能容纳完整物品奖励且钱袋未触及协议上限后，按 Enter 报名；已领彩头的重赛不受奖品容量/钱袋限制。Esc 离开报名页不计作尝试。
3. 按资料顺序挑战对手。每场使用通用 CombatSession，战斗胜利经验与伙伴援护照常生效；轮间不自动恢复生命或内力，鼓励备药与规划招式。
4. 一场胜利后自动开始下一场。任一场败北或撤退都会结束本次报名，不发夺魁彩头，但已胜场仍按正常战斗结算经验；首次完整连胜时发一次配置的银两和物品。之后的完整重赛仍记战绩、逐场给战斗经验，但不再发银两/物品。
5. 报名次数、最近胜场、历史最佳胜场和夺魁次数进入本地存档，以擂台资料 id 作为记录键。

## 内容协议

基础资源 arena.round-20-set 使用 arena-set Schema，位于 data/base/arenas/round-20-arenas.json。每座擂台声明稳定 id、名称/说明、地图入口、角色模板、按顺序排列的独立对手、完整通关奖励及交互文案。敌人的五项属性、生命/内力、武学、每轮经验、失败恢复比例与战报全部来自资料；真实战斗胜利始终发该轮经验。MOD 可按原相对路径提供同名文件覆盖。

加载期除 Ajv 静态 Schema 外，还检查地图资源及入口通行、出生点/NPC/野外遭遇/其他擂台占格、角色模板、敌方武学和奖励物品。一个跨资源引用无效只禁用受影响的擂台。删掉擂台资源时，世界照常启动且不显示入口。

## 状态边界

- 擂台对手不是地图遭遇，不占世界格、不从地图移除、也不产生任务遭遇胜负信号。
- 旧 v1 存档缺 arenaRecords 时解析为空记录册；本轮不提升存档协议版本。
- 已有 `championships > 0` 即表示首夺银两/物品彩头已经领取；旧存档不迁移，既有战绩中的夺魁次数自然封住重复经济奖励。
- 首夺彩头尚未领取时先检查奖品能否一起放入背包、银两是否有空间；首夺后重赛不需要为不会发放的奖品保留空间。
- 报名页清楚区分首夺奖励与仅更新战绩的重赛；彩头结算后刷新成就，确保擂台魁首奖励随首次战绩兑现。
- 目前战绩按当前资料的擂台 id 保存；资料删除后战绩仍留在本地快照里，不影响其他状态。

## 验证入口

- npm run validate:data：Ajv 校验 manifest 和每个登记的基础资源。
- npm run smoke:round-20：检查赛程解析/战斗适配/战绩格式及旧/新 v1 存档兼容。
- npm run build：TypeScript 检查及生产构建。
