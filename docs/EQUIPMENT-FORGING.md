# 装备锻造与强化（Round 24）

Round 24 将固定装备转换配方接入通用背包、装备、战斗与存档流程。锻造内容只由 JSON 声明；引擎不会给背包物品写入临时属性补丁，也不含具体工位、材料、装备名或剧情文本。

## 资料位置与 MOD

- `data/schema/equipment-forge-set.schema.json` 定义静态结构和值域。
- `data/base/forges/round-24-equipment-forges.json` 声明地图工位和配方，并由 `data/base/manifest.json` 登记为可选资源 `equipment-forge.round-24-set`。
- `data/base/items/round-06-items.json` 定义材料和进阶装备；商店/任务也可以提供配方所需材料。
- MOD 可用相同相对路径替换锻造文件，仍须通过相同 Schema、语义解析和跨资源装配；资源缺失或失效只关闭锻造入口。

## 工位规则

每个工位有唯一 `forge.station.*` id、显示名、`mapResourceId` 和 `{col,row}`。装配层要求地图资源存在、坐标可走，并隔离出生点、NPC、遭遇、擂台、门派战或其他工位占位冲突。有效工位格也加入 NPC 日程的固定占位，避免时段切换后 NPC 站上铁砧。

画面用“锻”标记工位。玩家站在四方向曼哈顿距离恰为 1 的格子时，E 打开配方面板；斜角和工位本格不算可交互相邻格。既有 NPC、遭遇、擂台与门派战继续按原交互优先级先处理。

## 配方契约

一条配方声明唯一 `forge.recipe.*` id、名称/说明、工位 id、2–8 种投入、正整数银两成本和结果 `itemId`。投入须引用当前物品集，且须恰好包含一件（数量为 1）装备；其他投入只能是 `misc` 材料。结果必须为装备，并与基础装备同槽；基础装备已有的任何属性/气血/内力加成不得降低，且至少一项必须严格提升。悬空物品、失效工位、跨槽或降级配方各自禁用，不影响其余有效配方。

锻造没有随机品质或重掷。想新增结果属性时，作者先在物品 JSON 定义一个普通装备 id，再让配方引用它。Round 24 的熟铁砂、韧皮料、青玉磨粉可从现有行商处购买；三件基础装备分别可转换为同槽强化版本。

## 交易与装备效果

制作前逐项检查银两、材料和装备持有量；已装备的投入装备须先卸下。引擎在库存副本上扣除所有投入，再检查产物空间并插入结果，最后一次提交银两、堆栈和装备槽状态；任何失败均不会部分扣料。扣料释放的格子可以用于接收结果，因此满包转换仍可能成功。

配方成功后用现有任务物品数量快照刷新收集目标。产物是常规 item 定义，可在背包中穿戴、参与属性调和和 `CombatSession` 伤害计算，也可出售（遵守正常商店价格）。游戏代码无需识别锻造物品的特殊实例状态。

## 存档兼容

Round 24 不新增快照字段或改变 v1 协议。背包依旧保存 `{itemId, quantity}`，装备槽保存 `itemId`；因此存档自然记录锻造成果。读取时按当前物品资料与现有 `equipItem` 流程重算属性和气血/内力上限。如果 MOD 移除了某个结果 item，标准存档预检会按普通失效物品规则过滤它。

## 验证

- `npm run validate:data`：检查 manifest 与所有登记基础 JSON Schema。
- `npm run smoke:round-24`：检查解析/跨引用/占位隔离、邻接、坏配方隔离、拒绝事务不变性、满包转换、实际战斗加成和 v1 存档装备重算。
