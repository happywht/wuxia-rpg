## 1. 工作标题与设定

**工作标题**：《墨痕江湖》（英文名 Inkmark Jianghu；仅为占位名，发布前可另定）

**设定概述**（全部为原创内容）：

架空王朝「大雍」末年，朝廷权威衰落，江湖门派各自为政。主角是江南小镇上一名平凡的抄书学徒，因一册来历不明的残缺武学抄本被卷入纷争，从此离开书斋步入江湖。玩家在由二十二个既有区域组成的开放江湖中自由行走：结识或得罪人物、拜入或对抗门派、修习乃至自创武学，所有选择被世界记录并累积，最终汇入由玩家行为决定的多种结局。

设计基调：**小屏时代"高密度选择"的江湖体验，在现代浏览器中以数据驱动方式重构**——以可步行的大区域承载探索，但让每一次相遇、每一句话都留下可追踪的痕迹。Round 51 将起始江南行旅区扩成 100×100 网格并采用网页 CC0 像素图集，镜头随角色移动；Round 52 校正地图地层坐标、为地图舆图加上数据地标与独立裁切视口；Round 53 依据碰撞网格提供地点/关口步行导航，并用见闻节点控制部分地点显露；小屏 UI、近距离互动与可移动地图继续强调清楚、可读的掌上 RPG 操作。

> 当前已落地世界的背景、区域地理、五派格局、药道会盟与叙事边界，以基础 JSON 为证据源整理于 [`docs/WORLD-SETTING.md`](WORLD-SETTING.md)；地图、对白与任务资料协议分别见 [`docs/MAP-ATLAS.md`](MAP-ATLAS.md)、[`docs/DIALOGUE-GUIDE.md`](DIALOGUE-GUIDE.md) 与 [`docs/QUESTS.md`](QUESTS.md)。

## 3. 核心循环

Round 20 在核心循环的“相遇/成长”之间加入了擂台挑战：玩家检查赛程和完整奖品后报名，连续使用现有回合制战斗，夺魁领取数据配置的彩头，失败/撤退战绩记入本地记录册。玩法详见 ARENA_DESIGN.md。

Round 21 增加资料驱动的门派战：两派弟子迎战对方门派的阶段对手，战斗贡献决定胜、平、负，结算后果改变双方门派声望和个人声望，并解锁图谱见闻与导师对白。玩法详见 `docs/FACTION_WAR_DESIGN.md`。

```
探索（行走地图 / 时间推进）
   → 相遇（NPC、事件、场所、发现物）
   → 抉择（对话选项、道德取舍、门派立场、武学取舍）
   → 变化（角色成长 + 江湖关系与认知图谱更新 + 世界状态演变）
   → 更大的世界（新区域、新剧情线、新结局路径解锁）
   → 回到探索
```

循环的四根支柱：

1. **自由探索**：不设强制线性主线，主要区域在满足极低门槛后即可进入。
2. **NPC 交互**：对话有分支与后果；NPC 记得玩家做过什么（见 §5.1）。Round 03 已落地数据驱动的 NPC 放置、邻接交谈与基础分支对话；Round 08 已落地任务/物品/善恶/江湖声望/关系条件分支与对话效果；Round 18 接入逐派声望条件和变化，知识图谱记忆联动在 Round 11 扩展；Round 19 加入可由关系门槛招募、跨区同行并提供战斗支援的伙伴。
3. **成长与武学**：属性成长 + 可修习武学 + 玩家自创武学（见 §5.2）。Round 04 已落地数据驱动的属性/经验/成长/派生协议与武学习得资格判定（等级/属性/门派）；Round 05 已落地武学战斗作用与首场数据驱动遭遇；师门授艺、自创武学、经脉内修、锻造与炼丹已有界面和规则；逐招熟练度仍需按协议核查，下一阶段优先验证成长与地区挑战的关联。
4. **江湖选择**：善恶、门派立场、恩怨情仇的选择累积决定结局走向（多结局由数据定义）。

## 4. 范围边界（明确不做的事）

- **不包含任何原作内容**：不复用原作角色、地名、剧情、文本、代码、美术、音频（详见 `docs/ORIGINAL-FIDELITY.md` 与 `docs/REFERENCES.md`）。
- **按轮次逐步扩展**：Round 00 建立工程与设计基线；Round 01 完成网格移动切片；Round 02 完成 manifest、Schema 校验、事件总线与基础 MOD 覆盖；Round 03 完成 NPC 放置、邻接交互与基础数据驱动对话；Round 08 完成对话条件与效果；其余系统按路线图逐轮实现。
- **不做多人/联网**：单机本地体验，Round 09 提供三个浏览器本地存档槽；不做云同步。
- **不承诺移动端原生适配**：仅保证浏览器内等比缩放可用。
- **音频为可选后期项**：没有音频的版本也视为完整可玩。
- **不做玩家自制内容编辑器**：mod 采用"同名 JSON 覆盖"的轻量方式（见 `docs/DATA-GUIDE.md`），不开发图形化编辑工具。

## 5. 玩家价值与计划新系统

### 玩家价值（为什么玩）

1. **被记住的江湖**：你的每个选择都被 NPC 关系图谱记录，并在后续相遇中回响——世界不大，但足够"记仇"也足够"念旧"。
2. **自己的武学**：武学不只是收集品，玩家可以组合元素自创招式并命名，形成独一无二的武功路数。
3. **活着的江湖**：时间、天气与生态让世界自行运转，NPC 有日程、场所有作息、资源会枯竭与再生。
4. **高密度抉择**：延续小屏武侠 RPG"小世界、多选择"的精神，但在数据与系统的支撑下让选择真正有长期后果。

## 6. 数据优先边界

- `src/engine/`：引擎运行时（渲染、循环、加载、校验、存档等通用机制）。**只认识数据协议，不认识任何具体世界内容**。
- `src/game/`：胶水层，把引擎能力接到 Phaser 场景与 UI。
- `data/base/`：全部世界观、角色、地图、任务、对话、知识图谱、物品、武学、门派、结局，一律为 JSON 数据。
- `data/schema/`：数据协议的 JSON Schema，含 manifest 和各内容资源契约；基础 manifest 登记的资源逐项指向 schema，Ajv 管线在加载基础资料与 MOD 覆盖时校验。Round 24–25 起也覆盖可选锻造/炼丹工位与配方。知识节点、关系各自使用独立 Schema。
- `mods/`：玩家/作者以同名文件覆盖 `data/base/` 内容的轻量 mod 层。

规则：**引擎代码中不出现具体设定文本**（角色名、地名、台词等），一切世界内容以数据进入游戏。详见 `docs/ARCHITECTURE.md` 与 `docs/DATA-GUIDE.md`。
