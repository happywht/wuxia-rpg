## 1. 工作标题与设定

**工作标题**：《墨痕江湖》（英文名 Inkmark Jianghu；仅为占位名，发布前可另定）

**设定概述**（全部为原创内容）：

架空王朝「大雍」末年，朝廷权威衰落，江湖门派各自为政。主角是江南小镇上一名平凡的抄书学徒，因一册来历不明的残缺武学抄本被卷入纷争，从此离开书斋步入江湖。玩家在一片高密度的小型开放江湖中自由行走：结识或得罪人物、拜入或对抗门派、修习乃至自创武学，所有选择被世界记录并累积，最终汇入由玩家行为决定的多种结局。

设计基调：**小屏时代"高密度选择"的江湖体验，在现代浏览器中以数据驱动方式重构**——世界不大，但每一次相遇、每一句话都可能留下痕迹。

## 3. 核心循环

```
探索（行走地图 / 时间推进）
   → 相遇（NPC、事件、场所、发现物）
   → 抉择（对话选项、道德取舍、门派立场、武学取舍）
   → 变化（角色成长 + 江湖关系与认知图谱更新 + 世界状态演变）
   → 更大的世界（新区域、新剧情线、新结局路径解锁）
   → 回到探索
```

循环的四根支柱：

1. **自由探索**：不设强制线性主线，主要区域在满足极低门槛后即可进入。
2. **NPC 交互**：对话有分支与后果；NPC 记得玩家做过什么（见 §5.1）。Round 03 已落地数据驱动的 NPC 放置、邻接交谈与基础分支对话；Round 08 已落地任务/物品/善恶/声望/关系条件分支与对话效果（接取任务、交付物品、修善良恶声望关系）；知识图谱记忆联动在 Round 11 扩展。
3. **成长与武学**：属性成长 + 可修习武学 + 玩家自创武学（见 §5.2）。Round 04 已落地数据驱动的属性/经验/成长/派生协议与武学习得资格判定（等级/属性/门派）；Round 05 已落地武学战斗作用与首场数据驱动遭遇；修炼界面、熟练度增长与自创武学在后续轮次。
4. **江湖选择**：善恶、门派立场、恩怨情仇的选择累积决定结局走向（多结局由数据定义）。

## 5. 玩家价值与计划新系统

### 玩家价值（为什么玩）

1. **被记住的江湖**：你的每个选择都被 NPC 关系图谱记录，并在后续相遇中回响——世界不大，但足够"记仇"也足够"念旧"。
2. **自己的武学**：武学不只是收集品，玩家可以组合元素自创招式并命名，形成独一无二的武功路数。
3. **活着的江湖**：时间、天气与生态让世界自行运转，NPC 有日程、场所有作息、资源会枯竭与再生。
4. **高密度抉择**：延续小屏武侠 RPG"小世界、多选择"的精神，但在数据与系统的支撑下让选择真正有长期后果。

| 2 | **玩家自创武学** | 招式由可组合元素（起手/发力/收势等）构成，玩家可在平衡约束内组合、命名并使用自创武学 | 设计完成（Round 00），待实现 |

## 6. 数据优先边界

- `src/engine/`：引擎运行时（渲染、循环、加载、校验、存档等通用机制）。**只认识数据协议，不认识任何具体世界内容**。
- `src/game/`：胶水层，把引擎能力接到 Phaser 场景与 UI。
- `data/base/`：全部世界观、角色、地图、任务、对话、知识图谱、物品、武学、门派、结局，一律为 JSON 数据。
- `data/schema/`：数据协议的 JSON Schema。当前包含 `manifest`、`grid-map`、`npc-set`、`dialogue-set`、`character-profiles`、`faction-set`、`martial-arts-set`、`battle-encounters`、`items-set`、`shops-set` 与 `quest-set` 共 11 份契约；基础 manifest 登记的 10 个内容资源均指定对应 schema，由 Round 02 接入的 Ajv 管线在加载基础资料与 MOD 覆盖时校验。尚未进入 manifest 的数据族（如知识图谱、结局和世界事件）仍须在接入前补充 schema。
- `mods/`：玩家/作者以同名文件覆盖 `data/base/` 内容的轻量 mod 层。

规则：**引擎代码中不出现具体设定文本**（角色名、地名、台词等），一切世界内容以数据进入游戏。详见 `docs/ARCHITECTURE.md` 与 `docs/DATA-GUIDE.md`。
