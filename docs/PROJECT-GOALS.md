# 项目目标：既有江湖的丰富、串联与细化

更新日期：2026-10-01。执行起点：Round 98（`cd1e74b`）；内容盘点基线仍为 Round 97（`c0d551b`）。本文件根据用户本次调整，规定下一阶段的产品目标；最初附件保留为历史需求。现状证据见 [CURRENT-STATE-AUDIT.md](CURRENT-STATE-AUDIT.md)，逐轮安排见 [ROADMAP.md](../ROADMAP.md)。本文中的“目标/验收”均为待实现要求，不是完成声明。

## 1. 持续有效的总目标

完成一款受文曲星掌上武侠 RPG 核心体验启发、世界内容原创的可运行 2D 武侠 RPG。玩家能在大世界中行走，结识人物、接受差事、拜师习武、战斗与制作、作出有后果的选择，保存旅程并抵达可解释的结局。

保持 ADR 已冻结的 TypeScript + Phaser 4 + Vite、Ajv/JSON Schema、通用引擎与 JSON 资料分离、跨资源校验、同路径 MOD 覆盖、本地存档兼容、授权素材记录。地图与像素人物继续使用核验来源的素材；可移动舆图、区域镜头与清晰的像素操作体验仍是产品要求。

原有 50+ 轮、人物/门派/任务/物品/武学/结局/知识节点数量下限继续有效，已达到的数量是内容基线。完整交付还必须通过以下体验验收；轮次、条目数、测试数、代码存在和历史结构审计不能单独作为产品完成判据。

## 2. 下一阶段的开发原则

先深化现有 22 个区域与 65 项差事。新增地图须在当轮计划中证明其承担已有地图无法承载的叙事或玩法角色，并说明对现有旅程的贡献。扩地图不再作为默认迭代主题。

把每个地区定义为枢纽、挑战区、调查区或过境区。枢纽应能补给、获得方向和接续任务；挑战区应有可读风险与成长回报；调查区应有发现、判断和人物回应；过境区应明确路线价值。无需把商店和战斗机械地铺满每张地图。

内容修改尽量复用已有系统与稳定资源 id；若真正的分支、限时、任务阶段或敌方策略需要新协议，单独规划引擎/Schema/MOD/存档迁移与旧内容回归，不用对白措辞伪装未实现规则。
