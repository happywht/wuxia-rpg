# 当前大目标：把既有江湖打磨成完整、可重复游玩的武侠RPG

更新：2026-10-04，Round270开始。严格执行用户要求的1→2→3→4→5顺序。当前状态与证据只在[验收矩阵](CURRENT-ACCEPTANCE.md)维护；历史见[开发日志](../DEVLOG.md)，不从历史active/通过推断当前Goal或候选版本。

## 推进顺序与完成门槛

1. **代表旅程**：先打磨江南—雾雨渡口—云岭60–90分钟旅程。串起出发动机、任务、有代价的选择、门派成长、制作实际用途、挑战和到达回报；逐段检查变化与必要回程。使用既有铁嶂连接道路，不虚构直达关口或残篇答案。该段完成后才推广到北境/海路。
2. **12项既有差事深化**：按[执行方案](PRODUCT-POLISH-PLAN.md)固定名单改造；同一困难至少两种有差异的解法，覆盖战斗、药物、关系、调查。不同消耗产生人物、商店或通行的可观察后果；独立QA分支验证代价、后果和读回。换一句对白不算新解法。
3. **成长、敌人和制作决策**：守御反击与轻身耗敌在同一挑战有不同决策；行动征兆可信，制作物解决实际地区困难。五派实践、两条材料→制作→用途循环有效。冷却、状态、熟练度按确定玩法需要补协议，保持资料驱动。
4. **信息与美术一致性**：Q当前任务/最近完成/预计与实际奖励清楚；E/F、导航、分页一致。统一合法像素素材的色板、建筑语言、人物辨识、遮挡层次，实走六代表地区，检查道路/入口/交互物。
5. **持续验证与交付**：独立QA存档和真实输入阶段检查点，推进整段、保存、读回、记录；互斥两侧分角色，修复后重验受影响项。锁定候选，完成三章、结局、兼容、MOD、空坏资料、许可和独立发行实启。

QA隔离/矩阵在阶段1前作为工具建立，不代表阶段5通过。维护性优化贯穿各阶段：按实际改动抽离探索、任务、成长、存档协调模块，避免向约5000行grid-scene.ts集中装配。保持技术栈与稳定资料ID，默认深化22区/65差事。

## 不可缩减的八组全局验收

1. 正常新游戏、首差事、补给、战斗、拜师、习武、出镇、跨区、保存/读回真实闭环。
2. 大陆、北境、海路各至少两个既有区域，每章至少两处有代价的决定，残篇阶段答案和后果可观察。
3. 至少12项既有差事实质深化，覆盖调查、战斗/习武、物品/制作、人物立场。
4. 22区职责明确；江南、渡口、云岭、青帆埠、照雪关、澜心洲有可比较的真实行路/入口/补给测试，问题修复复走。
5. 五派地区实践、至少两条材料→制作→用途循环、两条代表挑战成长路线。
6. 至少8名既有NPC、3组跨区关系和伙伴立场有可观察变化。
7. 至少3种结局承接三章实际决定，关键后果正常保存/读回保留。
8. 同一交付版完成三章键盘旅程、关键分支两侧、中途存读、旧v1、MOD、空坏资料降级、Schema、素材授权和独立发行实启，留下可复现证据。

原始要求共同有效：可运行核心玩法及指定界面；引擎无具体人物、地点、剧情/任务硬编码；资料Schema校验、同名MOD覆盖、空坏资料可读降级；NPC≥10、门派≥5、任务≥20、物品≥50、武学≥30、结局≥3、图谱节点≥100；至少3项原创扩展；文档、原作对照、REFERENCES齐全；Round00至Round50+至少50轮，每轮计划/实现/验证/文档/独立提交。数量下限已达到，不能代替体验和交付。

## 执行纪律

- 每轮先plan，含故事、验收、至少两个可验证子任务、文件、风险、人类工程师估时≥10分钟；实现代码/资料/文档、验证、更新CHANGELOG/DEVLOG/ROADMAP，创建round-XX提交并按轮汇报。
- 玩家正常三槽受保护；QA存档/设置隔离。不得直接修改任务、见闻、等级、时钟或资源伪造检查点。导出的共同真实检查点可用于独立双分支，必须记录来源。
- 实现、自动测试、当前候选实机、跨版本历史分别记录。60–90分钟是体验目标，游戏时钟、等待工具和AI操作墙钟不能冒充真人首玩时间。
- 新引擎能力有玩法用途与资料/存档边界；抽离覆盖事件次序和实际入口，不以大重构延迟旅程。
- 单轮结束、数量达标、自动绿灯、历史三个结局或包文件生成均不等于整体完成；全部门槛成立才关闭Goal。
