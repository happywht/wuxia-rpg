# Round 64：三图七时段交互目标路线审计

## 审计口径

`tests/round64-route-audit.test.ts` 是可复现的 Phaser-free 审计：直接装入江南道、雾雨渡口、铁嶂北道三张 100×100 地图与世界舆图，按世界加载器同样的方式逐图运行 `assembleNpcPlacements` 合并全部 14 名 NPC，用 `compileNpcSchedules` 对七个历日时段编译占位，并装入全部野外遭遇。

审计对象为**交互关键目标**：每个登记门派的全部师父（5 个门派各 1 人）、每项差事的给予者与每个 `talkToNpc` 目标引用的人物，按 NPC id 去重后共 **14 个**，全部通过装配存在性检查。区域入口取起始图出生点与每条有向关口的落点，按地图格去重共 **5 个**：江南道 2 处、雾雨渡口 2 处、铁嶂北道 1 处。

可达性判定与运行时一致：从入口对地图几何（`canEnter`）做一次 BFS 得到可达格集，目标视为可达当且仅当其四向邻格中存在可走且落在集合内的格子——这正是 `findGridPathToAdjacentCell` 把玩家停到交互格旁的契约。审计分两层：

- **静态层**：不带任何占位，只看地图几何。静态不可达意味着地图数据断连，属于必须修复的缺陷。
- **动态层**：对每个时段，把该图当期 NPC 占格与固定遭遇格计入阻挡（入口格除外——运行时 `resolveNpcPlacementsForPlayer` 会把玩家所在格让开，审计同样豁免）。动态不可达意味着活占位封路。

从每一个起始/入区格分别审计本图全部交互目标与全部出图关口的 `from` 格（走到关口旁是跨区行程的必要条件），因此每一段行程入口→关口→每个有向落点都被覆盖。

## 结果

| 指标 | 数值 |
|---|---|
| 地图 / 时段 / 不同入口格 | 3 / 7 / 5 |
| 交互关键目标（师父+给予者+谈话对象，去重） | 14 |
| 路线检查（目标/关口×入口×静态+动态） | 462 |
| 静态断连 | **0** |
| 动态阻挡 | **0** |

七个时段 × 三张地图、五个不同入口格的全部 462 项检查中，没有出现静态断连或动态阻挡：每个师父、给予者与谈话对象在其所属地图的每个时段位置，都能从该图每个区域入口走出一条避开当期 NPC 与遭遇的相邻交互格路线；每张图的出图关口从每个入口同样全程可达。本轮**没有发现需要修复的交互关键阻挡**，因此未改动任何地图或日程数据。

审计同时作为回归护栏：任何地图改版、日程调整或新增交互目标若造成断连或封路，将直接使 `tests/round64-route-audit.test.ts` 失败并逐条打印失效条目（地图、时段、入口、目标与格坐标）。

## 边界说明

- 审计覆盖"入口 → 同图交互格"的可达性；跨区长途的逐格步行、天气步耗时与换班跟随已由 Round 63 的实时时钟模拟覆盖（见 [`ROUND-63-TIMED-ROUTE-AUDIT.md`](ROUND-63-TIMED-ROUTE-AUDIT.md)），本轮不重复。
- 动态层豁免入口格的 NPC 占位，与运行时玩家安全放置逻辑一致；若未来引入会主动追堵玩家的移动占位，需另增针对性模拟。
- 本审计衡量几何与占位可达性，不代表人工试玩体感，也不验证任务奖励平衡。
