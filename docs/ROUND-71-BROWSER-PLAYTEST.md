## 实际操作

1. 新建角色「抄书学徒」，开局位于江南 `(43,37)`，游戏时间 08:00。
2. 用方向键到石阶渡口相邻格 `(90,51)`，按 E 过图到雾雨渡口 `(1,4)`，09:52；再走到雾岬北口相邻格 `(88,15)` 并按 E，进入铁嶂北道 `(4,7)`，12:15。
3. 走到石脊西道相邻格 `(52,89)` 并按 E，进入西陲盐道 `(95,74)`，15:10。按资料轨迹到青岩驿附近 `(49,49)`，于 16:21 与罗金子交谈并选择「我替你去回声苦井核对水线。」；对话反馈显示已接取「苦井辨线」。
4. Esc 打开暂停菜单，保存一号槽。刷新 5189 页，从主菜单选择继续及一号槽；画面恢复盐道 `(49,49)`、第 1 年青阳 1 日 16:21。该恢复画面保存在 [`evidence/salt-road-restored.png`](../iterations/round-71/evidence/salt-road-restored.png)。
5. 从恢复点走到 `(26,28)`，画面提示「新见闻【回声苦井】已记入江湖见闻」。随后尝试使用生成轨迹回到青岩东关；它与当时游戏路线不一致，人物实际停在 `(32,30)`，17:13。这里没有把路线终点或尚未打开的结局界面写作已通过。
6. 在当前位置打开 M 舆图、G 切换本区细图，选中「青岩东关」后，游戏显示由 `(32,30)` 重新计算的 107 格路线，首段为东行 46 格。重新规划结果证明舆图按实时地图/坐标生成导航。后续回到关口、返渡口及结局 UI 尚未实际操作。

刷新前一号槽保存成功画面见 [`evidence/salt-road-save.png`](../iterations/round-71/evidence/salt-road-save.png)。

## 引擎轨迹与浏览器差异

`npm run generate:round-71-browser-trace` 调用 `tests/round68-long-journey.test.ts` 的真实资料回归，将 749 格模拟行程、5 次关口交互及保存/继续检查点写入 [`../iterations/round-71/browser-trace.json`](../iterations/round-71/browser-trace.json)。Round 71 轨迹测试验证方向串的格式、格数、起止坐标和关口顺序。资料回归独立验证整条行程可以完成，但固定方向串在浏览器里的回程偏离了路线；游戏内重规划给出的是当前坐标下的有效路线。浏览器没有验证全程 749 格，也没有验证终章门或结局页。
