# 本地存档与设置协议

Round 09 引入本地单机存档。存档是运行时状态的版本化 JSON 快照，不是世界资料：不会写回 `data/base/`，也不会被 MOD 覆盖。协议实现位于 `src/engine/save-system.ts`，菜单与游戏场景负责呈现和调用。

## 槽位与存储

- 使用浏览器 `localStorage`，有三个固定槽位：`slot-1`、`slot-2`、`slot-3`。
- 键名为 `wuxia-rpg.save.<slotId>`；主音量和文字大小独立存放在 `wuxia-rpg.settings.v1`。
- 开始菜单可继续或删除现有存档；游戏内按 Esc 打开暂停菜单，可将当前进度写入任一槽位。
- 存档摘要显示角色名、等级、地图位置和最近保存时间。写入前先生成 JSON 并验证版本与字段；损坏快照不会覆盖现有槽位。存储被禁用或空间不足时会报告错误，设置仍可在当前会话生效。
- 任何时候均不自动清空其他槽位；删除只作用于玩家明确选择的槽位。

## 快照内容

每份快照包含 `protocolVersion: 1`、保存时间、角色模板 id、玩家显示名、地图资源 id 与网格坐标，以及以下状态：

- 等级、累计经验、基础属性、当前生命/内力、已掌握武学 id。
- 银两、容量、物品堆叠和装备槽。
- 商店剩余库存。
- 任务阶段、每项目标进度及当前跟踪任务。
- 善恶、声望、逐 NPC 关系。
- 已完成的一次性战斗遭遇。

快照只保存 JSON 安全的数组/普通对象；不会保存 Phaser 对象、对话面板会话或可从角色模板和装备重算的派生属性/生命内力上限。读档时会按当前有效数据重新计算派生值。

## 安全恢复与资料变化

1. 读取槽位后，`parseSaveSnapshot` 防御性检查协议版本、必填字段、重复 id、整数范围和状态边界；未知额外字段被忽略，以便向后兼容。
2. `planSnapshotRestore` 对照当前已加载世界预检。角色模板、当前单地图资源或不可通行/被占用的位置不匹配时，整份存档拒载，玩家仍留在菜单。
3. 次要引用已经从世界资料删除时，恢复计划会逐项移除无效武学、物品、商店、任务、关系或遭遇，并提供警告；容量、物品堆叠、角色属性和任务目标进度按当前资料的新上限收敛。
4. 只有预检成功后才创建并恢复运行状态，装备重新经过装备引擎应用效果；不会把半恢复的状态提交到场景。

当前只实现 v1，不做旧版本迁移。未知版本会明确报告为不支持，原槽内容保留。存档仅限浏览器本地与当前单地图；跨设备同步、多地图位置和云存档尚未实现。浏览器清理站点数据也会移除本地存档。

## 设置

设置独立于存档槽：主音量为 0–10 档，实际应用到 Phaser 声音总线；文字大小为小、标准、大、特大四档，通过公共 UI 字号函数缩放界面。设置页调整后立即生效并尝试保存；存储不可用时仅本次会话有效。缺失/损坏设置使用默认值，不会在读取时覆写原值。

## 验证边界

Round 09 使用临时、Phaser 无关的冒烟 harness 验证序列化、字段拒绝、槽位操作、失败存储、世界变化预检及运行状态恢复；该脚本验证后删除，正式 Vitest 基线仍安排在 Round 38。浏览器手动流程验证开局/角色创建、保存入口和槽位摘要显示。
