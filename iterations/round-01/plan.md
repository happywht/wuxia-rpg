# Round 01 计划

## 本轮目标

完成可运行的 2D 垂直切片：显示一个由 JSON 数据描述的小型网格地图，玩家可用方向键/WASD逐格移动，墙体和地图边界阻挡移动。即使地图文件缺失或无效，应用仍应启动到清楚可读的错误/空世界画面。

## 用户故事

- 作为玩家，我希望启动后立刻看到一个简洁的武侠 RPG 网格场景，并能用键盘探索。
- 作为玩家，我希望无法穿过墙体或走出地图，移动结果与画面一致。
- 作为资料作者，我希望地图布局与碰撞规则在 JSON 中维护，不需要修改通用引擎代码。
- 作为维护者，我希望地图文件被删除或损坏时仍能看到可读反馈，而不是白屏或控制台异常。

## 验收标准

1. `npm run dev` 可启动游戏画布并显示数据文件定义的网格地图、玩家标记和通用操作说明。
2. 方向键及 WASD 每次只移动一格；墙体、地图边界阻挡移动。
3. 地图地块类型、布局、出生点、颜色和阻挡属性来自 `data/base/maps/round-01-grid.json`，引擎逻辑不包含具体人名、地名、剧情、任务或对话文本。
4. 地图缺失、HTTP 加载失败、JSON 无法解析或结构不合规时，仍呈现可读的空世界/错误状态。
5. 更新 Round 01 开发日志、变更日志和路线图；记录手动验证步骤及结果，执行并提交 `round-01: ...`。

## 可验证子任务

1. **数据地图与渲染**：定义轻量地图 JSON 协议、静态数据发布方式和 Phaser 网格渲染器。验证：启动后格子数量、墙/地面位置与 JSON 一致；损坏数据触发友好错误界面。
2. **网格移动与碰撞**：增加键盘映射、逐格移动、边界/墙碰撞和移动锁。验证：手动连续移动、尝试穿墙/出界，确认角色位置正确且无穿透。
3. **文档与回归**：整理本轮文档及运行命令。验证：`npm run build` 成功，浏览器手动操作可复现验收结果。

## 风险

- Phaser 4 与 Phaser 3 的缩放/输入 API 细节不同；只使用当前已安装 Phaser 4 API 并在浏览器实际操作验证。
- 网格移动若允许多个按键重入可能跳格；需在动画完成前锁定移动。
- Vite 静态数据目录与打包路径若不一致会导致开发正常、生产缺地图；开发服务器与生产构建都要检查资源路径。
- 数据 Schema 正式校验与事件总线属于 Round 02；本轮只做地图必要的运行时结构检查和可读失败处理。

## 预计人类工程师工时

约 2–4 小时（地图协议/渲染 45–75 分钟，移动/碰撞 45–75 分钟，异常降级与手动验证 30–60 分钟，文档与提交 20–30 分钟）。
