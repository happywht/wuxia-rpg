# Round 07 计划

## 本轮目标

在现有地图、NPC、战斗与背包上实现可独立运行的数据驱动任务闭环：玩家可从任务发布人处查看并接取任务，随物品和战斗进度追踪目标，达成目标后领取数据声明的经验/银两奖励，或因明确失败条件/主动放弃而记录失败。任务引擎保持 Phaser 无关；不实现 Round 08 的对话条件与效果，也不实现计时/日历、任务链脚本或持久化。

## 用户故事

- 作为玩家，我希望能在地图上找到任务发布人，查看任务说明、目标和奖励，并决定是否接取。
- 作为玩家，我希望能随时打开任务日志，查看进行中、已完成与已失败的任务，并跟踪一项活动目标。
- 作为玩家，我希望战斗胜负与背包物品变化能推进任务；目标完成后能立即收到明确奖励反馈。
- 作为玩家，我希望在无法继续时放弃任务，并且数据声明的失败条件会将任务记为失败。
- 作为资料作者，我希望通过 JSON 声明任务发布人、目标、前置任务、失败条件和奖励；坏引用只隔离相应任务/发布入口，不影响地图与其他系统。

## 验收标准

1. 新增 draft-07 `quest-set` schema、可选 manifest 资源与原创任务数据；任务、目标、奖励字符串和数值来自 JSON。
2. Phaser 无关任务引擎能解析/索引资料，逐条校验重复 id、发布 NPC、物品/遭遇/前置任务引用；支持 offered/locked/active/completed/failed 生命周期、目标进度、单一跟踪目标、主动放弃与失败条件。
3. 完成任务自动且恰好一次发放声明的经验与银两；物品数量变化/战斗胜负可驱动目标或失败条件；缺失的可选任务资源不会阻断既有世界。
4. 地图新增数据声明的任务发布 NPC；E 打开对应任务名录，Q 随时打开任务日志。玩家可以接取、跟踪/取消跟踪、放弃活动任务；日志展示状态、进度与奖励；任何面板打开时移动锁定，关闭后恢复。
5. 至少两条原创任务可验证不同路径：收集物品并完成奖励、击败既有遭遇并完成奖励；败于声明遭遇时任务失败。R00–R06 行为保持可用。
6. 更新 README、ROADMAP、CHANGELOG、DEVLOG、GDD、ARCHITECTURE、DATA-GUIDE；运行 build 与临时引擎/schema 检查及浏览器手动验证，清除临时验证文件；提交 `round-07:` commit。

## 可验证子任务

1. **任务数据与校验装配**：新增 quest-set Schema、基础任务集和发布人；将 quest-giver 属性加入 NPC 契约；跨引用逐条隔离无效任务/入口，登记为可选数据。
2. **Phaser 无关任务状态机**：实现任务解析/索引、锁定与接取、物品数量/战斗事件进度、失败与放弃、跟踪状态和一次性经验/银两奖励结果；用临时脚本检查正常路径、坏引用、重复事件和失败边界。
3. **任务名录/日志及场景联动**：新增键盘任务面板和地图接线；E 打开发布人名录、Q 切换日志；背包/交易/战斗结算向任务引擎发送变化并刷新 HUD/奖励反馈；验证地图移动锁与恢复。
4. **文档、整体验证与提交**：记录本轮实际结果、空集与失败降级及内存态边界；生产 build 与浏览器回归后清理临时文件，按规定提交。

## 风险

- 收集进度需要在接取时以当前物品数初始化，并在消费/交易后重新核算；否则开局已有物品或出售/使用导致的数量减少会显示错误。
- 战斗胜/败只在遭遇结果确定时通知任务系统，不能在面板中途关闭时误发奖励或误判失败；同一结果事件不得重复奖励。
- 经验升级、银两与任务状态需要按统一路径更新；任务奖励本轮不含物品，避免背包满时产生不可交付/半完成状态。
- NPC 可选字段缺省必须继续兼容旧资料；无任务/schema/发布人时其余对话、战斗、商店、背包仍可运行。
- 任务和跟踪状态仅存内存，刷新后回到新游戏状态；存档留给 Round 09。
