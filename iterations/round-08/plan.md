# Round 08 计划

## 本轮目标

把对话从静态节点跳转扩展为可校验、可执行的数据驱动条件与效果，并连接 Round 07 任务、Round 06 物品，以及本轮新增的声望/善恶和 NPC 关系状态。条件不满足的选项不可见；选择选项时效果校验成功后才转移节点，避免失败操作留下半套状态。保留 R07 任务名录和日志，不实现 R09 存档或 R11 知识图谱。

## 用户故事

- 作为玩家，我希望对话会根据已接/已完成任务、当前物品、声望和与 NPC 的关系显示不同选择。
- 作为玩家，我希望交付或取得物品、接受任务、改变名声或关系时看到明确反馈，失败选择不会扣错物品或产生半完成结果。
- 作为资料作者，我希望用 JSON 声明对话条件和效果；错误定义只禁用相应对话选项/对话，不影响地图及其他有效内容。

## 验收标准

1. 扩展 dialogue-set draft-07 Schema 与 Phaser 无关解析/校验，条件和效果是明确枚举的协议、拒绝未知字段/类型；旧的无条件对话仍兼容。
2. 至少支持任务状态、物品数量、玩家善恶/声望和指定 NPC 关系条件；条件组合按全满足判定，玩家只看见满足条件的分支，无可用分支时能正常结束对话。
3. 至少支持接取/放弃任务、给予/扣除物品、修改善恶/声望、修改对话对象关系等效果。执行时先验证前置条件和全部效果可行，再提交；任一效果失败不得留下物品、任务或社会状态的部分修改。
4. 社会状态由 Phaser 无关模块持有，标量有明确范围和边界钳制；对话状态在本次运行内存中，留存状态方案交给 Round 09。
5. 将条件/效果接入对话 UI 和地图场景；任务发布人同时保留对话与任务名录入口，既有任务日志、背包、商店、战斗及非条件对话保持可用。
6. 新增原创示例对话覆盖任务、物品、声望与关系分支；更新 README、ROADMAP、CHANGELOG、DEVLOG、GDD、ARCHITECTURE、DATA-GUIDE 和对话数据规范；执行临时引擎/Schema 检查、生产构建与浏览器手动回归，清理临时文件并提交 `round-08:` commit。

## 可验证子任务

1. **条件/效果协议与校验**：扩展对话 Schema、parser 和图装配，定义类型、值域与坏分支隔离规则；用 Ajv/解析器检查旧资料兼容、合法新定义和不合法定义。
2. **运行时状态及事务执行**：实现条件求值、社会状态、任务/物品效果适配及原子提交；验证前置不满足、背包容量、物品不足、重复任务状态、边界钳制与完整回滚。
3. **对话 UI/场景与原创内容接线**：隐藏不可用选项、执行选项效果并呈现反馈；E 保留普通对话，任务发布人另可打开 R07 名录；示例对话覆盖任务、物品、声望、NPC 关系。
4. **文档、整体验证与提交**：更新项目文档与路线图，运行构建、引擎/Schema 冒烟和浏览器回归，删除临时验证文件，提交本轮。

## 风险

- 对话效果横跨任务、背包和社会状态，必须在全部可行性检查通过后统一提交；背包容量或任务当前状态可能让效果被拒绝。
- 过滤掉所有选项后不能卡住输入；普通无条件对话需完全兼容。
- 任务收集目标以当前物品数量驱动，若对话扣除任务物品，须同步重算活动任务进度并明确目标可能回退。
- R07 当前把任务发布人按 E 打开名录；新增对话入口时须同时保留两种交互并明确显示按键提示。
- 声望、善恶、关系仅本轮局部运行时值；后续 Round 18 统一声望规则，Round 09 负责持久化。
