# Round 09 计划：角色创建、主菜单、存档与设置

## 本轮目标

把当前刷新后自动从固定模板开始的垂直切片，升级为有可返回主菜单的开局流程：玩家可创建角色、从本地存档槽继续游戏、在游戏中手动保存，以及调整并记住界面设置。存档格式需版本化、运行时校验，并在资料版本变化或内容损坏时给出可读提示。

## 用户故事

- 作为新玩家，我希望先看见主菜单并从有效角色模板中创建角色，以便开始一局属于自己的江湖旅程。
- 作为回归玩家，我希望查看存档槽摘要并读档，以便刷新页面后接着探索。
- 作为玩家，我希望从暂停菜单保存进度、返回主菜单或改动设置，以便掌控游玩节奏和体验。
- 作为资料作者，我希望存档不依赖 Phaser 对象，并能在数据不兼容时安全拒绝，而不是载入半坏状态。

## 验收标准

1. 应用启动后先呈现主菜单；新游戏支持选择可用角色模板并录入显示名，随后才进入地图。
2. 至少提供 3 个命名存档槽；可新建/覆盖保存、读档、显示槽位摘要与时间，并能删除存档。
3. 存档包含版本、地图位置、玩家状态、背包/装备、商店库存、任务阶段与目标进度、社会数值/关系、一次性遭遇完成状态和角色显示名；Map/Set 序列化为 JSON 安全数组/记录。
4. 存档读写经过独立解析与版本校验；损坏、过旧或与当前资源引用不兼容的存档不应用，界面显示可读错误且当前运行状态不被部分覆盖。
5. 菜单在游玩时可通过 Esc 打开；关闭后键盘移动和已有对话/背包/任务流程正常。
6. 至少 2 项设置可持久化，并实际影响体验（音量与显示缩放或文字大小）；不支持的设置不展示。
7. `npm run build`、存档引擎边界检查及浏览器手动流程通过；文档说明存档协议、槽位行为和已知限制。

## 子任务（均可单独验证）

1. **存档协议与存储适配器**：定义纯数据快照、版本化 Schema/防御式解析、localStorage 槽位 API、格式错误与配额异常结果；用临时 harness 覆盖 round-trip、破损输入、版本不匹配和槽位操作。
2. **开局与角色创建菜单**：将当前自动开局改为载入资料后显示菜单，加入新游戏角色模板/名称选择与继续/存档入口，保留数据缺失时的错误页。
3. **游戏进度恢复与暂停菜单**：从快照恢复玩家、物品、任务、关系、库存和遭遇；从地图位置校验失败时拒载；加入 Esc 菜单和明确保存反馈。
4. **设置、整合验证与文档**：加入持久化音量/界面缩放或文字大小设置，记录架构与操作文档，完成手动验收、更新路线图和开发日志。

## 风险

- Phaser 场景载入和菜单状态交错，可能导致恢复前先显示或重置新游戏状态；需让恢复校验先完成再提交运行状态。
- 任务、关系、商店库存使用 `Map`，必须显式转换为纯 JSON 记录/条目并在还原时检查边界。
- 角色模板或地图在资料更新后变化，旧存档可能引用已删除内容；以数据 id 和协议版本做完整预检，失败时保留菜单且不局部载入。
- localStorage 不可用、内容损坏或空间不足时必须保留当前游戏并给出反馈；浏览器测试不得把既有用户存档当作临时数据清空。
- 本轮不引入云同步和多地图持久化，避免把范围扩展到 Round 10 的区域切换系统。

## 预计人类工程师工时

**10–14 小时**，包括协议设计、Phaser UI 接线、状态恢复、异常路径和手动浏览器验收。
