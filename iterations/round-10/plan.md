# Round 10 计划：世界地图、区域切换与区域事件

## 本轮目标

让玩家从现有单地图探索进入一个由数据描述的多区域世界：在世界地图查看已登记区域，通过地图内关口往返切换区域，触发区域事件；读档时恢复当前区域与已完成的一次性区域事件。地图、区域节点、关口和事件文本均属于资料，不写入引擎常量。

## 用户故事

- 作为玩家，我可以打开世界地图，辨认当前所在区域和与之相连的区域。
- 作为玩家，我可以走到关口旁交互，在两个原创区域间往返；抵达位置安全且不会落进墙、NPC 或未完成遭遇格。
- 作为玩家，我可以在探索中触发区域事件；一次性事件不会因离开、回到区域或读档而重复触发。
- 作为玩家，我可以保存所在区域，在另一局启动后从同一地图和坐标继续；Round 09 已有存档仍能恢复。
- 作为资料作者，我可以在 JSON 中增删地图、区域、关口和事件，并通过 Schema/装配诊断发现悬空资源与不可走坐标。

## 验收标准

1. 新增 Phaser 无关世界地图资料协议与 draft-07 Schema，定义起始区域、区域位置、关口双向端点和区域事件；通过 Ajv 与防御解析，并按最小无效条目隔离引用/坐标错误。
2. 世界加载器收集并校验所有登记网格地图，解析世界图引用；首个地图继续作为默认起始区域，缺失起始地图或无效世界图给出可读错误。NPC/战斗遭遇按地图分别装配，跨区资料不得误放在当前区域。
3. 加入第二张原创地图与世界图资料，包含可往返关口和数据驱动的一次性区域事件。玩家可用 E 与相邻关口交互；每次切换验证目的地图、落点可走且未被占用，切换后正确重建地图、NPC、遭遇、HUD 与碰撞。
4. 加入 M 键世界地图覆盖层，展示所有有效区域及连接关系、当前区域，并在打开时锁定探索输入；对话、战斗、背包、商店、任务和暂停覆盖层继续正常工作。
5. Round 09 存档保存实际地图资源 id 和区域事件完成状态；恢复预检使用对应地图的几何与 NPC/遭遇占格。旧 v1 快照缺少新增区域事件字段时按空集合恢复，仍可恢复原始地图存档。
6. 更新地图图册、架构/资料指南、存档说明及 README、CHANGELOG、DEVLOG、ROADMAP；运行 Schema/解析/区域切换/存档兼容回归、生产构建、手动游玩流程，清理临时文件并提交 `round-10:` commit。

## 可验证子任务

1. **世界资料协议与多地图装配**：新增 world-map schema、无 Phaser 解析/引用校验、区域配置与第二张地图；改造 world-loader 以多地图加载，并逐地图组装 NPC/遭遇。
2. **地图旅行与区域事件**：扩展 GridScene 当前地图生命周期，添加关口交互、目的地安全检查、区域事件触发/去重和当前区域 HUD；实现世界地图覆盖层。
3. **存档兼容**：存档捕获当前地图 id 和已完成事件；恢复预检在目标地图检查走格/占位，旧 Round 09 v1 快照字段缺省兼容。
4. **验证与交付**：Ajv、纯引擎、真实世界资料、旅行/回程/事件/保存读档回归；更新文档和日志、清理临时 harness、构建并提交。

## 风险

- 现有 NPC/遭遇装配器带有 `currentMapResourceId` 语义，必须逐地图运行并保持全局 id 唯一、同格冲突检查与原地图行为一致。
- 地图切换需同时更新瓦片层、玩家、NPC、敌人、交互索引和 HUD；漏更新任一层会造成隐形阻挡或旧区域标记残留。
- R09 存档当前预检固定比较一个地图 id；扩展后须按快照地图验证坐标与动态占位，不能接受不存在区域或失效落点，也不能误拒旧存档。
- 一次性事件状态须与地图旅行/存档同步；事件触发、保存和恢复之间要避免重复发放或丢失。
- 世界图和地图资料均需从 manifest 资源解析，禁止在场景里硬编码区域 id、地点名、事件文本或传送坐标。

## 预计人类工程师工时

约 10–14 小时：资料协议与装配 3–4 小时；地图旅行、覆盖层与事件接线 4–5 小时；存档兼容 1–2 小时；验证、手动回归和文档 2–3 小时。
