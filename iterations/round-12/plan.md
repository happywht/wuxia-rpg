# Round 12 计划：小屏像素 UI、占位美术与操作可读性

## 本轮目标

把目前由纯色几何块和分散暗色矩形组成的画面，收敛成统一的原创掌机像素风界面：启用清晰像素渲染、升级地图与角色占位图形、统一菜单/面板边框及当前选择反馈，并提供一眼可查的键盘操作说明。修复探索态字号调整不刷新与 HUD 快捷键挤占地图标题的问题；战斗招式增多时使用焦点跟随窗口。保持 960×540 逻辑分辨率、原有键位和数据驱动世界内容；UI 只展示通用操作文案。

## 用户故事

- 作为玩家，我希望地图、角色标记和面板边缘在窗口缩放后仍保持清晰的像素层次，而不是发虚的矢量方块。
- 作为玩家，我希望当前选项有明显的底色/边条反馈，不必只靠颜色分辨自己选中了哪一行。
- 作为键盘玩家，我可以随时按 H 查看探索、面板和战斗操作；帮助页打开时不会误移动或触发世界交互。
- 作为资料作者，我可以继续仅用地图颜色和现有世界 JSON 运行游戏；本轮占位美术不引入外部素材，也不向引擎写入具体人名或剧情。

## 验收标准

1. Phaser 使用项目本地类型定义支持的像素抗锯齿/整像素配置，画布缩放和 CSS 样式清晰；网格边缘和玩家/NPC/敌人标记采用可复用、代码生成的像素层次。
2. 新增通用 UI 色板、面板 chrome 与选中行高亮 helper；主菜单、对话、战斗、背包、商店、任务、暂停、舆图、百科的面板视觉和当前焦点反馈统一，原有数据、按键和业务流程保持可用。
3. 地图中新增 H 键通用操作参考面板，解释探索和当前覆盖层操作；显示的键位与实际绑定一致，开面板时探索输入锁定，H/Esc 能关闭并恢复操作，且与已有面板互斥。探索 HUD 快捷键不再与地图标题占同一横向区域，设置页的字号修改关闭暂停菜单后立即刷新探索 HUD 与人物名牌。
4. 战斗选项超过可视行数时焦点滚动到可视窗口，逃跑选项仍可到达；在当前可用的窄视口手动浏览主菜单/创建角色、移动和 NPC 标记、百科、背包、任务、舆图、对话、战斗、暂停/设置，确认触发、移动与交互没有回归。记录视口宽度和未覆盖的标准窗口测试。
5. 更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`、README、GDD/架构或相关 UI 文档；运行 TypeScript/生产构建、资料 Schema 校验、`git diff --check`，记录真实结果并提交 `round-12:` commit。

## 可验证子任务

1. **像素渲染与地图占位美术**：验证 Phaser 本地 renderer 配置类型；启用 nearest-neighbor/roundPixels，绘制有层次的通用 tile 边缘、玩家小人及 NPC/敌人占位图形。
2. **统一界面主题与焦点反馈**：新增共享色板、双层像素边框和选中行 highlight；接入主菜单与全部主要覆盖面板，保留已有滚动和业务行为。
3. **操作帮助与输入回归**：新增 H 键帮助层、清楚分组的探索提示、全局覆盖锁；手动检验开关、输入锁及现有主要面板操作。
4. **小屏验收与交付**：在可用的窄视口手动核看字体/边距/边框，修正溢出，记录本环境无法设定标准视口的限制，更新文档/日志/路线图，构建与提交。

## 风险

- pixelArt/整像素显示会改变缩放时的锐度，需检查浏览器实际效果，避免放大清晰而缩小时文字发糊或闪烁。
- 通用面板 chrome 会影响叠层顺序和面板的已算好边界；必须逐类确认标题、长文案、滚动项和底部快捷提示都不被边框遮挡。
- H 键帮助层与地图/百科等快捷键共享输入系统；切换条件需先检查覆盖层是否打开，以免帮助层打开时误旅行、移动或开启第二个面板。

## 预计人类工程师工时

约 14–18 小时：像素渲染与程序占位美术 3–4 小时；主题/面板迁移及焦点反馈 5–7 小时；操作说明与输入集成 2–3 小时；多面板小屏核验、文档和修正 4 小时。
