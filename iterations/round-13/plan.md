# Round 13 计划：拜师、师门关系与退门规则

## 本轮目标

把目前仅作为门派志资料存在的门派扩展为可参与的玩家关系：玩家可向资料指定的师父申请拜师，入门条件由门派 JSON 配置；当前门派与师父关系可查询并随存档恢复；玩家可依门派退门规则离开，接受资料声明的声望/善恶代价与门派武学处理。所有身份、门槛、结果与对白留在数据层，引擎只实现通用协议。

## 用户故事

- 作为玩家，我能在地图中找到不同门派的师父，在对话里申请加入，并知道条件不足的原因。
- 作为门派弟子，我能查看自己所属门派与师父；重新读档后这段师承关系仍然存在。
- 作为玩家，我能从门派对话中退门，并在确认前看到由该门派资料定义的代价和武学处理规则。
- 作为资料作者，我能通过 faction/NPC/对话 JSON 定义导师、入门条件、退门政策和拜退选项；坏引用只影响相关条目，不破坏已有可玩内容。

## 验收标准

1. 扩展 faction Schema/解析器，支持导师 NPC、等级/善恶/声望/师徒关系/已完成任务入门门槛，以及可配置的退门许可、善恶/声望变化和门派武学去留；旧版未声明扩展字段的门派资料仍按宽松默认值读取。
2. 对话协议新增门派身份、武学资格条件和拜师/退门/授艺效果；拜师只接受当前对话中、由该门派登记的导师，必须未在其他门派，且全部门槛达标。退门只适用于当前所属门派，按数据规则原子应用代价、师父关系清除和武学处理；授艺使用既有等级/属性/门派资格算法；拒绝时不产生任何部分状态变化。
3. 扩展 v1 存档以保存 `factionId` 与 `masterNpcId`；较早 v1 存档缺少该字段时归一为无门派，资料变更造成的悬空门派/师父关系在恢复预检中可读地隔离，不误拒整份存档。
4. 三个现有门派各有可达的原创师父与对话拜退入口；新增 J 键师门页展示门派、师父、入门门槛和退门规则，并接入统一面板与输入锁/操作帮助。
5. 完成门派、师父与对白资料及 Schema/引用校验；更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`、README 和 GDD/架构/数据/存档文档；运行构建、资料 Schema 校验、引擎级情景验证、浏览器手动验收与 `git diff --check`，提交 `round-13:` commit。

## 可验证子任务

1. **门派规则契约**：增加向后兼容的 faction 入门/退门字段、Schema 与解析语义；扩展跨资源装配检查，识别导师 NPC、先决任务的坏引用。
2. **身份状态与存档**：新增 Phaser 无关师门状态/门槛判定，接入对话条件和原子拜师/退门/授艺效果；授艺接通已有门派武学资格检查，不扩展熟练度成长；为 v1 快照补充身份字段及旧存档缺省、悬空引用清理。
3. **原创师父与交互 UI**：每个现有门派配置一名可达师父和数据对白；新增 J 键师门查看面板；操作说明及探索面板互斥更新。
4. **跨系统回归与交付**：情景验证门槛拒绝/通过、重复拜师、退门惩罚/技能处理、保存加载和旧快照兼容；浏览器验证交互、文档/日志更新、生产构建与提交。

## 风险

- 对话效果是原子事务；新增身份、社交变化和武学遗忘必须都先校验、后统一提交，防止失败时只清空部分身份。
- v1 存档已积累多个可选字段；新增师门状态必须保持更早 v1 快照的缺省兼容，并检查 MOD 替换门派/师父资料后的恢复路径。
- 当前三个门派资料没有既定导师设定；新增三位原创导师和对白需保持立场、地图通行与现有人物故事一致，并且不把资料文本塞进引擎。
- 门派专属武学没有学习来源追踪；若门规选择离门遗忘，则按武学声明的 faction 适用范围处理，并在面板与退门反馈中清楚说明。
