# Round 14 计划：游戏内时间、历法与昼夜循环

## 本轮目标

为世界增加可持久化、可由玩家行动推进的游戏内时间；通过独立日历资料定义月份、每日时段、昼夜照度和动作耗时，并将时段提供给对白条件。显示原创历日/时刻，场景照明随时段渐变；不依赖现实系统时钟。

## 用户故事

- 作为玩家，我能看到当前历日、时刻和晨昼昏夜；行走、旅行或主动等候会推进时间，夜色也会在世界场景中显现。
- 作为资料作者，我能通过经过 Schema 校验的日历 JSON 调整月份长度、时段、照度和动作耗时。
- 作为对白作者，我能设置只在特定时段出现的选项；引用不存在的时段时，错误只影响该选项。
- 作为旧版玩家，我能继续读取没有游戏时间字段的 v1 存档，并从日历的起始时刻继续。

## 验收标准

1. 新增必需的 `game-calendar` 资源及 draft-07 Schema；月份至少包含稳定 id/显示名/天数，日内时段按起始分钟排序并声明照度；加载期语义校验拒绝无零点时段、重复 id、非法月份/时段或耗时。
2. 新增 Phaser-free 游戏时钟协议和纯规则，能按配置推进成功移动、区域旅行与 V 键等候；年月日、分钟、跨月/跨年及当前时段计算确定；暂停/对话等失败或被阻止的动作不消耗时间。
3. GridScene HUD 显示日期/时刻/时段，地图与人物层受时段照度渐变影响、操作 UI 保持清晰；H 帮助列明等候键，面板开启时不允许等候。
4. 对话图新增时段条件，集合解析、Schema、引用装配和运行时求值一致；缺失时段引用只剔除相关选项。v1 存档新增已过游戏分钟数；早期存档缺字段时以资料起始日期/时刻恢复。
5. 完成历法样例与文档说明；更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`、README、GDD、架构、数据规范、对白规范及存档文档；执行 build、完整登记资源 Ajv 验证、时钟/对白/存档情景验证、浏览器昼夜与读档手动验证、`git diff --check` 并提交 `round-14:` commit。

## 风险

- 月份长度可由资料修改，存档应保存经过的分钟数而非重复保存派生年月日，避免资料变化后出现互相矛盾的日期。
- 场景调色层必须夹在世界图像与 HUD/UI 之间，区域切换后也要覆盖新场景对象。
- 时段按循环边界计算，夜间横跨午夜；零点必须有定义且每段起点唯一，以免夜间条件在 00:00 失效。
- 等候、移动与传送只能在动作确实完成后推进时间；打开帮助/存档/对话等覆盖层不得借机推进。
- 历法是核心规则资源，缺失或无效需明确报错，不能静默退回与世界资料不一致的硬编码历法。
