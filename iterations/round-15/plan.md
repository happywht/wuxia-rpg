# Round 15 计划：季节与数据驱动天气

## 本轮目标

在 R14 历法上加入四季与逐日天气：季节/天气内容由必需的 climate 资源定义，天气按开局种子与历日稳定推导；天气影响探索场景和每步行走耗时，并能在存档读档后保持同一世界的天气结果。

## 用户故事

- 作为玩家，我能从 HUD 看见当前季节和天气；进入新的一天或季节后，环境表现会随天气改变。
- 作为行走中的玩家，我能感受到雨雪天气令每一步消耗额外游戏时间；晴朗等天气不增加成本。
- 作为资料作者，我能用 Schema 校验的 climate JSON 配置月份归属、季节天气权重、画面色调、降水样式和移动耗时。
- 作为旧版玩家，我可读取没有天气种子字段的 v1 存档，并获得稳定、可继续保存的气候结果。

## 验收标准

1. 新增 `climate` draft-07 Schema 和必需 `climate.base` 资料；加载期语义校验检查季节/天气唯一 id、月份完整且只归属一个季节、天气权重引用、视觉参数与行走附加耗时范围。
2. 新增 Phaser-free 气候规则：根据历法日期所在月份确定季节，以存档中的世界种子和已过游戏日确定每日天气；同一日期/种子结果稳定，跨日与跨季按新日期重新推导，不依赖现实时间。
3. GridScene 显示季节/天气，天气色调与自制降水粒子覆盖世界层而不遮挡 HUD/面板；粒子与色调在天气变化时更新。
4. 每次成功网格移动额外消耗当前天气配置的分钟数；失败/阻挡移动不消耗。区域旅行与等候保持 R14 耗时规则，不受天气额外步耗时影响。
5. v1 存档保存 32 位世界气候种子；旧存档缺字段时归一到稳定默认值，存档读取/保存后同一日天气不变。
6. 完成至少 2 组确定性/边界情景验证、全登记资源 Ajv 校验、生产构建、浏览器天气与移动实测、`git diff --check`；更新计划、CHANGELOG、DEVLOG、ROADMAP、README、GDD、架构、数据、存档和新增气候说明文档，并提交一个 `round-15:` commit。

## 可验证子任务

1. **气候资料协议**：新增 schema、原创四季与天气样例、manifest 注册、跨资料语义解析；覆盖坏引用隔离与必需资料失败诊断。
2. **确定性气候规则**：按日历月份映射季节，使用持久种子和游戏日索引作加权天气抽取；测试确定性、分布边界、年月交界和未知引用拒绝。
3. **运行时与存档接线**：新开局生成/读档恢复世界种子；GridScene 更新 HUD、天气色调/粒子并将天气附加耗时接入成功移动；保留旧 v1 缺字段兼容。
4. **验证与交付**：Schema/构建/气候与存档冒烟/浏览器检查，更新所有轮次日志和设计文档，检查最终 diff 并提交。

## 风险

- 气候以“种子 + 游戏日”确定，存档必须持久保存种子；旧 v1 迁移使用固定默认值，避免读档后无声改天气。
- 月份到季节必须形成无遗漏、无重叠的分区；Schema 能保证结构，跨资源引用需加载期语义检查。
- 天气色调/粒子与 R14 昼夜层叠放时须保留世界可读性，且在季节日切换后替换旧粒子对象，避免对象泄漏。
- 附加行走耗时只在网格移动成功后计入；天气不能改变关口旅行耗时或被阻挡移动的规则。
