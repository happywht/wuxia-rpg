# Round 16 计划：NPC 日程与时段地点变化

## 本轮目标

为 NPC 增加资料驱动的每日时段日程，让人物按历法时段更换所在网格位置；通过时间推进、读档和区域切换都能复现同一时段的人物分布。日程只定义世界资料，不在引擎中写死人物、地点或剧情。

## 用户故事

- 作为探索者，我在等候或行动跨过一个时段后，可以看到部分 NPC 按作息移动到新的地点。
- 作为交谈者，我接近 NPC 的当前所在格时仍能按原规则交互；NPC 迁走后，旧地点不会保留假碰撞。
- 作为资料作者，我可按 `periodId` 声明 NPC 的地图内位置；缺省时段沿用 NPC 的基础位置。
- 作为读档玩家，我的游戏时钟决定 NPC 当前日程位置，不需要重复存储或迁移 NPC 的派生坐标。

## 验收标准

1. NPC Schema 与防御解析支持可选日程表，日程每项关联有效历法时段与位置；同一 NPC 不得重复声明同一时段。
2. 加载期检查日程引用、地图边界/可走性/出生点、同一时段 NPC 之间的位置冲突，以及与固定遭遇格的占位冲突；错误可读并按最小人物/时段范围隔离。
3. Phaser-free 规则按当前历法时段解析 NPC 的有效地图位置；未声明该时段的位置回退基础位置；同一时段、地图和有效 NPC 集合结果稳定。
4. GridScene 在开局/读档、时段切换和跨区域旅行时同步 NPC 标记、名称、占位索引与交互目标；玩家当前所在格不得被日程人物覆盖；非时段变化不得重复重建日程。
5. 基础原创资料至少有 4 名 NPC 配置两种以上时段位置变化，覆盖两个区域和早/昼/夜等时段；不新增存档字段，旧 v1 存档按恢复后的 `elapsedGameMinutes` 派生日程。
6. 完成 NPC Schema/全 manifest Ajv 校验、Phaser-free 日程情景验证、生产构建、浏览器时段/交互/存读档实测和 `git diff --check`；更新计划、CHANGELOG、DEVLOG、ROADMAP、README、GDD、架构、数据/地图/NPC 说明并提交单个 `round-16:` commit。

## 可验证子任务

1. **NPC 日程资料协议**：扩展 NPC Schema 和解析接口；建立时段位置解析规则、重复时段/坏位置/冲突检查与失败诊断。
2. **世界装配与跨资源验证**：将日程对照必需历法、所有地图和遭遇资料验证；为每个日历时段生成可用 NPC 放置集合，保留默认位置回退与最小隔离。
3. **探索运行时接线**：按游戏时钟切换人物标记、标签、占格索引与交互提示；覆盖进入新区域及继续游戏路径，并避免覆盖玩家/遭遇。
4. **内容、验证与交付**：为多个原创人物编排跨地图日程；执行引擎/资料/浏览器验证并更新所有相关文档和开发日志，复核后提交。

## 风险

- NPC 日程会与玩家、遭遇或其他 NPC 抢占同一格；加载期按地图/时段检查，运行时切换再防御检查，不能阻挡玩家或把人物叠在固定遭遇上。
- 时段由历法数据定义，不能将具体时段 id 写死在通用引擎中；更换历法时悬空日程需有明确警告与隔离行为。
- 跨区域旅行会在耗时结算后跨过时段边界；区域装配必须使用抵达后的时段，不得沿用出发时的人物坐标。
- NPC 的活动坐标可由时钟与数据推导，因此不进存档；恢复时须先按旧档分钟数创建时钟，再同步 NPC 日程。
