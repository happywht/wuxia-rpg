# Round 17 计划：奇遇与传闻生成

## 本轮目标
将世界地图上的区域事件升级为资料驱动的奇遇触发器：支持线索、时段、天气门槛，并能在触发时发现知识图谱节点；错误的事件引用须隔离到单条事件。以渡口脚印线索串联一段可探索见闻，并将事件状态沿用现有 v1 存档字段。

## 用户故事
作为探索江湖的玩家，我在渡口初次发现脚印后，百科会记录这条线索；沿线走到芦苇边，并在合适的时辰/天气等候时，会触发新的传闻并解锁相关地点条目。条件未满足时事件不会被消耗，等候或再次进入时能继续触发检查。

## 验收标准
1. `world-map` 事件 Schema 与 Phaser-free 解析器都校验可选条件及 `discoverKnowledgeNodeId`；现有不带扩展字段的事件继续有效。
2. 事件装配期逐条校验图谱节点、历法时段、天气引用和坐标，坏事件只产生警告并被禁用，不影响有效事件或整张地图。
3. 运行时只有位置匹配且所有门槛通过时才触发；门槛失败不写入一次性完成状态；知识节点发现是幂等且可存档的。
4. 成功移动、抵达区域、以及原地等候后都会检查事件；同一格的多条有效事件可一并触发，旧事件行为不回归。
5. 基础资料提供至少一段“脚印 → 芦苇滩传闻”的探索链；更新区域事件/知识图谱/时间气候/Schema 文档，并记录本轮验证和工程量。
6. `npm run build` 成功；使用直接可运行的纯规则验证或浏览器手动检查覆盖通过/不通过门槛、发现线索与旧事件兼容。

## 子任务
1. 扩展纯数据区域事件协议、结构解析、Schema 和跨资源语义装配（坏行隔离）。
2. 编写纯规则事件门槛判定/触发状态处理，并接入网格移动、区域抵达、等候后的检查与百科知识发现。
3. 创作可达的渡口脚印/芦苇滩奇遇资料，补充图谱关系及文档中的协议/示例/存档说明。
4. 执行类型构建、Schema/加载验证与事件条件手动或脚本验证，修复问题，更新三份开发记录并提交。

## 风险
- 区域事件现在在场景层直接触发；必须避免将地图/人物/剧情常量塞入引擎，且语义坏引用只能禁用单条事件。
- 等候会覆盖区域提示；触发通知与等待摘要要合并或有明确优先级。
- 天气随日种子变化，手动复现门槛较难；纯规则层需可独立验证条件，示例链的初次线索不应依赖罕见天气。
- 已有图谱对话和 v1 存档使用 `knownKnowledgeNodeIds`/`completedRegionalEvents`；不得破坏旧数据、旧存档兼容与发现幂等性。
