# Round 20 计划：擂台挑战

## 本轮目标

加入资料驱动的擂台报名与连续挑战闭环：玩家可在世界中的擂台入口报名，逐场挑战擂主，完成后领取配置奖励，并在存档中保留挑战次数、最佳连胜场数与夺魁次数。擂台对手独立于野外遭遇资料，继续复用通用回合制战斗规则。

## 用户故事

作为江湖旅人，我想在擂台入口查看赛程与奖励、报名后连续对战，并在中途败退或夺魁后查看自己的战绩，这样就能反复检验武学成长并追逐擂台荣誉。

## 验收标准

1. 擂台资料在独立 JSON 资源中定义入口地图/格、赛程对手、完整通关奖励及可读提示；JSON 形状由 Schema 校验，坏的对手序列/跨资源引用可读告警并隔离对应擂台，Schema 不合规时可读降级该资料集。
2. E 键可与相邻擂台交互并报名；挑战按资料顺序逐场开启既有回合制战斗，胜利后自动接续下一场，败退/撤退会结束本次挑战。
3. 全胜后奖励按资料发放且只发放一次；每场战斗经验仍遵循既有通用规则；任务遭遇目标不会把擂台对手计为地图遭遇。
4. 擂台战绩持久化挑战次数、最佳胜场、夺魁次数和最近挑战胜场；Round 19 及更早的 v1 存档缺少新字段时安全默认为空。
5. 引擎与 UI 不硬编码具体人物、擂台名、台词或奖励；数据经 manifest/schema 校验并保持 MOD 同名覆盖约定。
6. 跑完项目构建、数据 Schema 校验和无 Phaser 运行时冒烟验证；将命令及结果记录到开发日志。

## 子任务（均可独立验证）

1. **资料协议与装配**：新增擂台 Schema/类型/解析器/跨资源装配；配置一座原创擂台与多轮对手，确认清单加载及坏引用隔离。
2. **报名和赛程 UI**：新增键盘操作的擂台面板，显示规则、轮次、奖励和战绩；接入相邻入口并将连续对手交给 CombatSession。
3. **奖励和存档战绩**：实现一次性全通奖励、胜场统计与旧 v1 存档兼容；核对解析、捕获、恢复流程。
4. **回归与文档**：构建并运行数据/引擎冒烟检查，补擂台设计说明、路线图及三份迭代日志，检查差异后提交。

## 风险

- 擂台连战跨多个战斗面板，需确保结算回调及时清理会话并锁住场景输入，避免重复领奖或错误地累计野外任务目标。
- 玩家可能在擂台途中保存/刷新；本轮只承诺持久化战绩，不在战斗覆盖层中途做可恢复快照，保存入口应继续被覆盖层锁定。
- 奖励容量或道具引用变化可能导致部分发奖；领取时使用现有背包容量规则并清晰提示，保证战绩清算与可领取奖励不会无声丢失。
- 旧 v1 存档须缺省新战绩字段为空，避免无必要地提升协议版本或破坏既有槽位。
