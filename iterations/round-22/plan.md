# Round 22 计划：玩家自创武学

## 本轮目标

实现玩家在游戏内组合招式、架势、吐纳三类资料组件，自拟名称并支付银两创制一门武学；引擎按透明的功力预算生成平衡属性，作品进入玩家已学武学并可参加战斗，且随存档往返。

## 用户故事

- 作为玩家，我想选取不同武学组件、为招式起名并看到效果/内力/花费预览，再决定是否创制。
- 作为玩家，我希望创制后立刻能在战斗招式列表中使用，读档后作品仍存在。
- 作为资料作者，我希望调整组件内容而不改引擎；组件资料坏掉时，主世界仍能启动并给出可读提示。

## 验收标准

1. 新增严格 JSON Schema 与 Phaser-free 组件解析/作品合成器；每门作品恰选一个招式、架势、吐纳组件，名称规范化，产生稳定自创 id。
2. 合成规则限制攻击/疗伤功力、内力消耗、综合预算与组件价格；重复名称、超过自创槽数、银两不足、缺组件或组合越界均拒绝且不改玩家/货币。
3. 新增 C 键创武面板，可选择三组组件、使用支持中文输入法的原生名称输入，预览效果/成本/预算，创建后提示并立即加入玩家可用武学；战斗复用现有 `CombatSession`。
4. v1 存档加入自创武学完整定义；旧存档缺字段默认空数组。存档解析再次验证 id 前缀、容量、唯一名称和功力上限，恢复预检允许作品 id 保留、过滤失效引用。
5. 组件资料登记在可选 manifest 资源并支持同名 MOD 覆盖；缺失/错误组件只禁用创制入口，不阻断地图/其他武学。
6. 更新操作手册、武学/存档/架构文档、CHANGELOG、DEVLOG、ROADMAP；运行生产构建、全资料校验与无 Phaser 冒烟，并提交 `round-22:` commit。

## 可验证子任务

1. **组件协议与合成规则**：定义三槽组件 schema、引用/重复校验、名称/id 规范和预算/收费公式，纯函数覆盖合法、负内力、超功率及空缺/越界组合。
2. **创制界面与战斗集成**：增加键盘面板和原始键名录入，原子扣款/登记作品，合并玩家自创武学到普通遭遇、擂台、门派战会话。
3. **存档兼容**：捕获完整作品、旧 v1 默认为空、严格解析并在恢复计划中以作品 id 满足玩家已学引用，验证作品往返与坏作品拒绝。
4. **文档与验证**：更新 C 键帮助及相关系统文档、路线图/日志，运行 build、data validation、专用冒烟、上一轮回归与差异检查。

## 风险

- 存档是用户可编辑 JSON；恢复时必须复验自创 id 命名空间、作品数量/名称、战斗效果上限，避免绕过创制器的平衡预算。
- 多个会话共享战斗地图，需只扩充给玩家的武学查表，不允许敌人或资料引用解析依赖玩家作品。
- 名称录入须支持中文输入法组合；编辑焦点不可把方向键/动作键穿透给地图，关闭面板时需解绑并移除临时输入控件。
- MOD 可调整组件，因此合成器必须对数据定义也做合理值域与组合预算校验。
