# Round 23 计划：经脉与内修

## 本轮目标

建立可替换的经脉网络资料与 Phaser-free 内修规则：角色升级获得资料配置的修为点，玩家另按节点配置消耗药物/材料打通满足等级/前置条件的节点；节点效果作用于战斗属性和气血/内力上限，解锁及未用点数可随旧 v1 存档兼容往返。

## 用户故事

- 作为玩家，我想看到当前修为点、经脉节点、等级/前置条件、药物材料成本和效果，选择内修路线。
- 作为玩家，我希望升级后获得修为点，打通节点后立刻感受到属性/气血/内力提升，读档后保留。
- 作为资料作者，我希望用 JSON 配置修为获取、经脉依赖、等级门槛、成本和效果；坏资源只关闭内修系统。

## 验收标准

1. 新增可选 `meridian-set` 资源、严格 JSON Schema 和 Phaser-free 解析/语义校验；节点 id 唯一，等级/成本/效果限界，前置引用存在且无环。
2. 数据声明初始修为、每级修为与存储上限；经验结算按实际升级数增加点数并限上限。节点可列物品 id/数量为消耗材料，世界装配验证物品引用；内修事务先检查点数、材料、等级、前置和重复状态，拒绝时不改点数、背包、节点或角色属性。
3. 经脉节点可配置基础属性、气血上限、内力上限加成；加成不重复叠加，装备变化/升级重算结果一致，战斗读取已增强角色状态。
4. N 键面板展示修为余额、所有节点状态、效果、门槛/前置及选择说明；打通后即时刷新，面板输入不穿透到地图；操作帮助同步更新。
5. v1 快照保存未用修为点和已打通 node id；旧档缺字段默认为 0 点/空数组。损坏值拒绝，MOD 移除节点时恢复仅过滤无效节点并给出 warning；恢复后依据当前资料重算加成。
6. 节点/修为资源由同名 MOD 文件覆盖；缺失或错误时世界与既有成长/战斗继续启动，只有内修入口禁用。
7. 更新 GDD、数据/架构/存档与内修说明、CHANGELOG/DEVLOG/ROADMAP；生产构建、全资料 Schema 校验、R23 专项冒烟和上一轮回归通过，并提交 `round-23:` commit。

## 可验证子任务

1. **资料协议与经脉规则**：定义节点 Schema/解析/依赖 DAG 检查、升级发点、可学习判定、效果汇总和拒绝原子性。
2. **角色/战斗接线**：在角色状态中维护修为、节点 id 与独立加成；升级和装备重算保留经脉效果，并使三个玩家战斗入口使用增强状态。
3. **存档兼容**：捕获/解析/恢复新字段；旧 v1 缺省兼容、非法余额拒绝、移除节点过滤、恢复后的效果重算。
4. **资料/UI/验证与文档**：新增原创经脉资源、N 键面板和操作提示；运行 build、data validation、Round 23/22 冒烟及差异检查。

## 风险

- 经脉效果、升级成长和装备加成都作用于同一组有效属性/派生上限；必须分开记录来源并从基础值重算，避免重复叠加或被换装覆盖。
- 存档允许用户编辑；修为点、node id、节点数量和效果范围都需再次防御校验。
- MOD 可覆盖节点图；缺失/坏前置/循环须给出可读诊断并按可选系统降级，悬空材料引用隔离该节点及依赖节点；移除已打通节点时不能拒绝整份存档。
- N 键只在探索态打开，节点效果写入须即时刷新 HUD/战斗依赖，并阻止方向键穿透。
