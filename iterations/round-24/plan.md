# Round 24 计划：锻造与装备强化

## 本轮目标

新增数据驱动的锻造站与装备进阶配方。玩家在地图工位附近交互，消耗一件未装备的旧装备、材料和银两，获得装备资料集中预先定义的更强装备；新装备仍走既有背包、穿戴、战斗与存档协议。

装备强化采用“旧装备 + 材料 → 数据定义的进阶装备”转换形式：数值、槽位和最终名称由普通 item 数据定义，不在存档中写临时属性补丁。该形态能让 MOD 替换配方/结果，并沿用 item id 保存与恢复语义。

## 用户故事

- 作为玩家，我想在地图的锻造工位查看每个配方的材料、银两、产出装备和强化后属性，判断是否值得打造。
- 作为玩家，我希望配方材料、旧装备、货币或背包空间任一不足时操作不改变背包/银两；材料齐全时才获得新装备。
- 作为资料作者，我希望用 JSON 定义工位、配方、投入与结果 item 引用，并用同名 MOD 覆盖基础锻造内容。

## 验收标准

1. 新增可选 `equipment-forge-set` 资源与严格 Schema；工位坐标/配方/物品引用由 Phaser-free 装配校验，坏工位及依赖配方、坏配方按最小资源单元隔离并提供诊断。
2. 工位须在有效可行走格，不能与出生点、NPC/日程、遭遇、擂台、门派战或其他工位冲突；仅四方向相邻可按 E 打开工位面板。
3. 配方必须消耗同槽未装备基础装备、数据定义材料及正银两，产物必须是同槽且不削弱原加成的装备。制作先验证全部条件及扣料后的产物容量，再原子提交，任何拒绝均不改背包、货币或角色属性。
4. 面板展示选中配方的每项投入、当前库存、货币、输出装备属性/气血/内力加成与可制作原因；输入由面板独占，成功制作即刻刷新。
5. 材料可通过现有商店/任务闭环获得；制造出的输出装备可按既有装备流程穿戴、参与战斗计算并正常存档读档，无需增加实例属性存档字段。
6. 配方资料支持同路径 MOD 覆盖；经锻造资源缺失/无效时地图、商店、装备和战斗仍可运行，仅工位/锻造入口禁用。
7. 更新 CHANGELOG、DEVLOG、ROADMAP 与相关 GDD/架构/数据/作者/存档文档；构建、全资料 Schema 校验、R24 专项冒烟和 R23/R22 回归通过，提交 `round-24:` commit。

## 可验证子任务

1. **资料契约与装配**：实现锻造 Schema、解析器、工位格/recipe/item 跨引用校验、逐条隔离及 MOD 登记。
2. **锻造事务规则与经济闭环**：实现可制作判定、克隆库存预演、原子扣除旧装备/材料/银两并生成进阶装备；补齐原创材料与可购买库存。
3. **地图交互与 UI**：添加工位标记、邻接选择、E 键选择配方面板、属性预览、拒绝原因、输入锁与即时反馈。
4. **验证、存档证明与文档**：专项测试引用隔离/冲突/事务拒绝/产物穿戴战斗/普通 v1 保存往返，更新所有轮次文档和回归。

## 风险

- 槽位不匹配会让打造物不可合理替换原装备；装配必须检验输入/结果装备槽位相同。
- 装备作为配方投入时可能仍穿在角色身上；制作前拒绝消耗任何已装备输入，以免有效属性和背包状态分叉。
- 先扣材料后检查产物容量会丢失物品；必须在克隆背包上试扣与插入并整体提交。
- 自定义强化属性若写在背包实例上会破坏 v1 存档与 item 数据边界；本轮结果限定为普通 item 数据定义的固定进阶装备。
- 多张地图和 NPC 日程可能使工位不可达或被占用；工位装配必须对所有已知时段 NPC 占位做冲突校验。
