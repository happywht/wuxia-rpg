# Round 27 计划：数据驱动的多结局判定

## 本轮目标

加入可替换、可校验的结局资料集：以地图中的终章入口汇总当前任务、善恶、江湖声望、NPC 关系、门派身份/门派声望和已知见闻，计算哪些结局已达成；玩家可查看未解锁线索并选择一个结局，读完原创终章后返回主菜单。引擎只解释条件和呈现资料，不保存或硬编码剧情结局。

## 用户故事

- 作为玩家，我希望一路完成的差事、为人取舍、人物关系和门派选择共同决定我能抵达的结局。
- 作为玩家，我希望在终章入口看见所有结局的锁定/可达状态与尚缺条件，并在可达结局间作选择。
- 作为资料作者，我希望只通过 `data/endings/` 与知识图谱增删结局、条件、地点和叙事，不改引擎规则。
- 作为 MOD 作者，我希望缺失结局资料时其他游戏系统照常启动，单条坏结局/坏条件引用不会屏蔽其余结局。

## 验收标准

1. `ending-set` JSON Schema 与防御解析器验证终章入口、唯一结局 id、结局知识节点和封闭条件协议；可选资料缺失可用，单条结局的跨资料坏引用隔离并产生警告。
2. 条件覆盖任务状态、善恶、个人声望、NPC 关系、门派身份、门派声望和知识节点；数值上下界闭区间；评估是纯函数、稳定排序，不修改任务/角色/社会状态。
3. 终章位置从资料声明，经地图可通行格、出生点、NPC、战斗/活动入口、关口与事件交叉校验；仅相邻可交互。玩家可浏览已锁/已达结局及数据驱动文本，确认后锁住探索输入，并可明确返回主菜单。
4. 基础资料至少有三个原创结局，且条件分别体现行为/任务/关系组合、门派/声望/关系组合与可抵达的开放式归宿；结局知识节点加入图谱。
5. Round27 专项 smoke 覆盖条件边界、每类门槛、锁定原因、结局排序/选择、引用隔离、门口格验证和输入状态；资料校验、R26–R24 回归、生产构建通过。
6. 新增结局设计/作者指南，并更新架构、GDD、数据指南、图谱说明及 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`；完成后提交 `round-27: ...`。

## 可验证子任务

1. **结局协议与规则引擎**：定义 Schema、解析器、跨资料条件引用校验、纯函数评估和门口格装配/邻接选择。
2. **地图入口与结局体验**：接入世界装配、程序化门口标记、E 键相邻交互、锁定提示/选择/结局呈现和返回主菜单状态。
3. **原创结局内容与知识图谱**：写入三个互有差异的结局、可玩门槛、图谱节点/关系，验证基础游戏中的入口位置无占格冲突。
4. **专项/回归验证与文档**：编写 Round27 smoke，执行数据校验、相邻版本回归、生产构建和差异检查，更新文档与日志。

## 风险

- 资料语义损坏要按结局/地点最小粒度隔离，避免可选内容让整片地图无法启动。
- 玩家初始状态通常达不到高阶结局条件；必须同时提供至少一个清晰可达的归宿，并让示例门槛可由当前差事/门派玩法实际获得。
- 终章解析只可读取运行状态，选择结局前不应消耗物品、改任务或关系；终章显示期间所有探索输入都必须被面板接管。
- 结局 id 对应知识图谱节点，MOD 删除节点或地图后要给出可读警告并禁用相应条目。
