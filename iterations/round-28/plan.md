# Round 28 计划：可替换成就、进度与奖励

## 本轮目标

实现资料驱动的成就集，覆盖当前成长、任务、社交、知识、战斗和制作系统。成就条件以 AND 组合并展示逐项进度；首次满足时幂等解锁并自动发放资料声明的经验/银两奖励。解锁状态和战斗/制作计数随现有 v1 存档保存，旧档缺字段时兼容为空基线。玩家可用独立面板查看成就、进度、锁定提示和奖励。

## 用户故事

- 作为玩家，我希望自己完成差事、了解江湖、精进武学和参与活动时看到持续进度，而非只有结局时才回顾选择。
- 作为玩家，我希望达成条件后立即知道成就已解锁并取得一次性奖励，存档读档后不会重复领赏。
- 作为资料作者/MOD 作者，我希望通过 JSON 添加成就、组合门槛并定义奖励，坏条目不会关闭有效成就。

## 验收标准

1. 新增封闭的 `achievement-set` Schema、可选 manifest 资源和防御解析器；重复 id、非法范围及悬空人物/门派/知识引用按单条成就隔离；缺资源时其他世界内容继续运行。任务条件以完成数量为单位，不声明单个任务引用。
2. 条件含角色等级、完成任务数量、已知知识数量/指定见闻、善恶、江湖声望、门派身份、人物关系、战斗胜利数、擂台夺魁、经脉数、自创武学数、装备锻造次数和炼丹次数；进度模型对可计数量值展示 current/target，对区间/布尔条件显示当前值和目标。
3. 纯函数评估当前旅程，跨资料装配校验定义；条件全部达成时只解锁/奖励一次。奖励由 JSON 声明经验和银两，溢出按角色经验/存档货币上限安全截断。
4. 存档以 v1 可选字段保存解锁 id 和新增单调计数器；Round 27 及更早 v1 快照缺字段按空集合/0 兼容。成就 id 保持历史性：临时移除 MOD 成就再启用时不会重复发奖。
5. G 键成就面板展示锁定、进度、解锁和奖励；场景在战斗、任务、物品/进度变更、制作及成就页打开等收口点检查新解锁，提示只出现一次。
6. 基础资料含至少 10 条成就，覆盖至少 3 个当前可抵达玩法；Round 28 smoke 覆盖协议边界、进度、纯度、解锁/领奖幂等、旧档兼容、MOD 隔离及完整世界加载。
7. 更新成就、存档、数据/架构/GDD/操作说明及 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`；运行专项烟测、R27–R25 回归、资料校验、类型检查与生产构建，提交 `round-28: ...`。

## 可验证子任务

1. **资料协议与评估规则**：Schema、逐条防御解析、跨资料引用装配、纯函数评估/进度投影和一次性领奖状态转换。
2. **存档与玩法收口**：扩展 v1 可选成就快照；接入战斗胜利、锻造、炼丹计数及当前任务/图谱/门派/等级/经脉/擂台事实；达成条件时单次发奖。
3. **成就界面与基础内容**：G 键列表面板、进度/奖励/锁定提示、解锁提示，以及 10 条原创成就数据。
4. **专项验证与文档**：新增 Round 28 smoke，验证旧档与 MOD 边界及完整 world-loader，并更新相关说明和日志。

## 风险

- 成就仅靠打开面板才评估会漏掉反馈；必须在任务、战斗、制作等有限收口点重评，且再打开面板可见最新状态。
- 老存档可能在新成就条件发布前已满足门槛；恢复后首次评估会补发一次成就奖励，需由持久化解锁 id 保证之后不重复。
- 经验/银两有上限，超出部分不能破坏存档范围；成就奖励不可依赖物品背包容量或部分扣款。
- 成就资源及其条件引用是可选内容；坏的单条资料只禁用自身，不能让世界加载或其他成就失效。
