# Round 29 计划：江湖图鉴与百科收集进度

## 本轮目标

沿用现有知识图谱作为唯一词条来源和 `knownKnowledgeNodeIds` 作为唯一持久化发现状态，新增可独立打开的收集图鉴：按人物、地点、门派、物品、武学、事件、任务、结局展示已发现/总数、完成比例和保密锁定行；补齐探索过程中人物、地点、已持有物品和已学武学的通用发现钩子，让百科收录不依赖作者为每条物品或武学重复添加对话效果。

## 用户故事

- 作为玩家，我希望能一眼看到江湖各类见闻的收集进度，并在发现后读到与 K 键百科一致的资料。
- 作为玩家，我希望首次接触人物、抵达地点、获得图谱中列出的物品或学得列出的武学时，图鉴会自动记录，读档后继续保留。
- 作为资料/MOD 作者，我希望继续只编辑知识图谱节点及其 `knownByDefault`，不必再维护一套重复的图鉴标题和描述；未知条目的名称与详情继续保密。

## 验收标准

1. 新增 Phaser-free 进度投影 API；进度按图谱节点分类，空分类安全显示，统计结果不修改知识图谱或传入的发现集合。
2. 新增图鉴 UI，显示 8 类收集数量和进度、已知条目、锁定占位及选中类别详情；操作支持分类切换、条目浏览、Esc 关闭。新快捷键不与现有 J 师门、K 百科、M 舆图等冲突，操作帮助列出该键。
3. 场景在有效会面/交互时发现同 ID 人物；抵达同 ID 地图资料节点时发现地点；已知背包物品和已学武学同 ID 图谱节点时发现条目。战斗遭遇可选声明图谱人物节点，玩家首次面对遭遇时解锁对手人物。已有对白/奇遇/炼丹/门派战事件发现保持不变，重复发现幂等；继续使用既有 v1 存档字段，不新增冗余状态或升级版本。
4. 新增 Round 29 专项烟测，覆盖分类统计、隐藏节点、空类别、幂等与只读纯度，以及基础知识图谱上人物/物品/武学/地点的 ID 收录语义；UI 由类型检查和代码路径核查验证。
5. 更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`，以及操作说明、知识图谱/百科和架构文档；记录全部验证命令和结果，并按格式提交一个 Round 29 commit。

## 可验证子任务

1. **图鉴规则与展示**：实现只读分类进度投影及独立键盘图鉴面板，验证计数/保密/滚动/分类边界。
2. **发现钩子与兼容**：接入人物会面/战斗对手、地图抵达、背包获得和已学武学检查，复用已有知识发现集合并验证旧 v1 存档路径无变化。
3. **专项验证与资料更新**：添加可运行烟测与快捷键说明，更新知识图谱、架构、GDD 和本轮开发记录，执行类型/资料/构建及 R28 回归。

## 风险

- 快捷键拥挤会导致误触或覆盖现有操作；实施前确认空位并同步更新操作手册。
- 图谱 id 与业务 id 必须明确匹配；只对同 ID、同预期 kind 节点解锁，MOD 删除节点或加入无对应运行时事实的节点时应保持安全。遭遇的人物见闻通过可选 graph-node 引用并在装配时检查 character kind。
- 背包物品可能在物品面板关闭前已消耗；收录必须在面板的成功变更回调以及任务奖励、对白效果和制作等发放收口处检查，并且一经发现永久留在现有存档集合。
- 新旧 v1 存档以图谱和 `knownKnowledgeNodeIds` 派生进度，不新增版本字段；MOD 词条变化后只计当前有效节点。
- UI 尺寸需照顾 960×540 基准和字号设置；条目超出可视窗口时需分页/滚动，不得截掉最后一条。
