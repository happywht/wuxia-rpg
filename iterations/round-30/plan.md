# Round 30 计划：原创人物、门派与关系资料扩充

## 本轮目标

扩充原创江湖资料，使基础世界达到至少 10 名可交互 NPC 和 5 个可校验门派；补齐新人物的传记、关系和人物与门派/地点/事件间的知识图谱边。新增人物必须能在现有地图中遇见并拥有资料驱动对话；新增门派使用现有拜师/退门规则，不为本轮另造引擎分支。

## 用户故事

- 作为玩家，我希望在渡口及镇中遇到有不同立场、生活经历和实际诉求的江湖人物，而非只看到数量占位。
- 作为玩家，我希望新增门派的师长可通过现有对话规则收徒，并且门派信条、入门门槛与人物行为彼此一致。
- 作为资料作者，我希望在人物志、门派表和知识图谱中查看人物的师承、隶属、旧识和行动地点，并能按 Schema 验证这些资料。

## 验收标准

1. `data/base/characters/round-03-npcs.json` 至少含 12 名 ID 唯一、地图/对话引用有效且实际放置可达的 NPC；新增 NPC 总数为 3 名。
2. `data/base/factions/round-04-factions.json` 至少含 5 个 ID 唯一门派；新增两个门派均有原创立场、理念、武学风格、有效导师及可由现有拜师系统评估的入门/退门规则。
3. 两名新增导师拥有可用的资料驱动拜师/离门对话；第三名新人物有与人物志、图谱关系及场景职责一致的对话。manifest 中任意数量的 `dialogue-set` 资源均由通用装配器合并，跨文件重复对话按声明顺序保留首条；引擎改动不得包含剧情、人名或门派名。
4. 新增人物志与门派说明文档；知识图谱至少新增对应人物、门派节点和有效关系边，人物/门派/地图/对话 ID 均可跨资源验证。
5. 新增 Round 30 专项烟测，验证数量下限、全局 ID 唯一、地图位置可行、导师引用、门派规则装配、关系图边引用和新对话可解析；全套资料 Schema 验证、类型检查、生产构建通过。
6. 更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md` 与数据/人物资料指南；保留 51 轮以上路线图；提交单一 `round-30:` commit，提交前确认不包含已有未跟踪的 `.serena/` 用户目录。

## 可验证子任务

1. **角色与门派设计及资料落地**：新增 3 名原创 NPC 和 2 个门派，核对每条资料与其地图、门槛、现有社会规则一致，并让两名新导师可通过数据对话收徒。
2. **人物志与关系图谱**：新增人物志文档及门派资料，添加对应图谱节点/关系边，确保无重复 ID、无悬空端点，所有名称与故事只存在于数据和文档。
3. **资料接线、校验和回归**：登记新对话资源，补充 Round 30 专项烟测，运行资料校验、类型检查、生产构建和必要回归，记录结果并提交。

## 风险

- 仅达到最低人数会形成空洞内容；新增人物需分别承担传递地方知识、门派招收或跨门派议事等明确职责，并在对话中体现其人物动机。
- 新 NPC 可能和现有角色日程、出生点、遭遇或互动格冲突；放置必须依地图 walkability 与现有调度校验，坏点位不得静默重叠。
- 新门派导师对白若引用不存在的武学、任务或条件，会形成表面可见但不可用选项；本轮优先复用已存在的通用规则与明确可验证的条件。
- 知识图谱关系词须符合现有 Schema；不为叙事方便扩展未实现的关系语义。
- 多个对话资源的装配必须维持 manifest 顺序、重复 ID 确定性和逐资源故障隔离；不能让新增一个坏的可选对话文件阻断地图或其他玩法启动。
- 新门派将被既有图鉴和结局系统纳入枚举，但不应误触发只为三家基础门派编写的专属终局；需检查现有按 faction ID 定义的专属条件。

## 预计人类工程师工时

约 14–20 小时：人物和门派设定/资料表 4–6 小时；人物志与关系图谱 3–4 小时；对话与场景摆放 2–4 小时；跨资源专项烟测、兼容回归、文档与提交 5–6 小时。
