# Round 33 计划：知识图谱覆盖与结局关系闭环

## 本轮目标

扩展基础知识图谱，使其覆盖当前实际 NPC、地图、门派、物品、武学、任务、剧情事件和结局，并让已有结局的可判定条件能在百科关系中追溯。当前 54 个节点未覆盖多数目录资料；本轮以真实资源稳定 ID 为准补齐，而非只追加无运行关联的占位词条。

## 用户故事

- 作为玩家，我希望已经见过的人物、取得的物品、学会的武学和接触的任务都能在百科中找到一致条目，并看到它们与门派、地点和后续归宿的联系。
- 作为资料作者，我希望每种结局的任务、人物、门派和见闻条件都能沿图谱追溯，并能由专项校验及时发现漏项、错类或断开的引用。
- 作为 MOD 作者，我希望图谱继续沿用现有封闭 Schema 与资源覆盖路径，新增资料不改变存档格式或引擎协议。

## 验收标准

1. 图谱至少 100 个节点；基础人物、地点、门派、50 件物品、30 种武学、20 个任务及 5 个现有结局均按业务稳定 id 映射到正确 `kind`。预计节点总数为 134（含现有剧情与额外叙事节点）。
2. 所有节点和关系 id 唯一，关系端点都存在且 Schema 有效；新增物品能追溯到商贩持有库存或锻造配方，门派武学能连到门派，任务能连到发布人及前置/目标，结局的图谱节点与可判定条件关系完整。
3. 保留至少 3 个可由现有结局系统判定的结局；每条结局依然引用 `ending` 节点，基础五条结局各自可达条件无悬空引用，结局条件对应的图谱关系可由烟测核验。
4. 新增 `smoke:round-33` 专项烟测，验证覆盖率、唯一性、类别、引用、结局条件及资料间连通；运行 Round 27/32 专项烟测、资料 Schema 校验、类型检查和生产构建。
5. 更新 `docs/KNOWLEDGE-GRAPH.md`、`docs/ENDINGS.md`、`docs/DATA-GUIDE.md` 与 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`，清除过期节点/关系计数；本轮新增 `iterations/round-33/plan.md`，最后创建唯一一个 `round-33:` commit。

## 可验证子任务

1. **目录事实映射**：把当前基础物品、武学、任务、NPC、地图、门派、事件和结局与图谱 id 对齐；补充缺失节点及对应关系，并覆盖所有结局路线来源。
2. **图谱一致性烟测**：增加 Round 33 脚本，断言数量、业务目录映射、唯一 id、有效端点、商品/锻造路径、武学归属、任务发布人与链路、结局条件边。
3. **文档与回归**：修订图谱/结局/数据指南中的实际计数与玩法说明，运行 schema、类型、专项及邻近系统回归和生产构建，更新路线/日志后提交。

## 风险

- 图谱摘要可能泄露尚未发现的剧情；新增节点默认发现状态应按现有运行时规则区分，结局仍默认未知。
- 结局关系应表达实际判定条件，避免为了边数加入无意义关联；任务目标若引用遭遇等非图谱实体，不能伪造节点类型。
- 本轮仅扩展数据与校验文档，不改变引擎协议和存档格式；须确认 MOD 移除节点时既有逐条引用隔离仍适用。

## 预计人类工程师工时

约 18–26 小时：目录与关系盘点 3–4 小时；80 个稳定节点及约百条关系的编辑/交叉核对 6–8 小时；专项烟测与失配修复 4–6 小时；文档、回归与提交 5–8 小时。
