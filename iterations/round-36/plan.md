# Round 36 计划：开发模式资料热重载

## 本轮目标

在 Vite 开发模式下监听 `data/` 与 `mods/` 下 JSON 的新增、修改和删除，通过自定义 HMR 事件通知游戏重新校验并装配资料。菜单刷新可用人物资料；游戏内刷新重建依赖资料族，并在新资料通过存档兼容预检后保留当前角色与进度。生产构建不接入开发热重载。

## 用户故事

- 作为内容作者，我修改地图、人物、对白、任务或 MOD JSON 后，希望无需手工刷新浏览器，就能在游戏里检查新资料及校验告警。
- 作为开发中的玩家，我希望重载重建依赖资料时保留当前角色、背包、任务、关系、时钟和地图位置；新资料与当前进度不兼容时得到可读错误，而不是半更新状态。
- 作为发布者，我希望开发工具链只在 Vite 开发服务器生效，不将热重载运行时代码或开发端点带入生产包。

## 验收标准

1. Vite 插件只把仓库内 `data/**/*.json` 与 `mods/**/*.json` 的 add/update/delete 转成自定义资料变更事件；忽略源码、依赖、非 JSON 与越界路径，并阻止 Vite 对这些资料变更执行整页刷新。
2. 浏览器端开发桥接按短时间窗合并重复通知，暴露可取消订阅接口；场景关闭或 HMR 替换时释放监听，生产模式不注册事件。
3. 主菜单收到变更后重新加载并装配资料，当前页面可用的人物模板/错误状态同步更新；进入游戏后仍通过共享 `loadWorldData` 使用最新结果。
4. 游戏场景收到变更后等待移动、战斗和覆盖面板结束，再原子地重载世界资料；使用当前 `SaveSnapshotV1` 对新世界做现有兼容预检，保留可迁移的运行状态。新资料无效或当前位置/引用无法恢复时显示可读失败，不部分替换运行字段。
5. 新增 Round 36 专项烟测，覆盖安全路径分类、Vite 自定义事件及抑制默认 reload、客户端批量通知/退订、非 JSON 忽略；生产构建、类型检查和既有 R35/R34 回归通过。
6. 更新 README、`docs/ARCHITECTURE.md`、`docs/DATA-GUIDE.md`、CHANGELOG、DEVLOG、ROADMAP；记录 Vite 手动资料变更演练结果和明确限制；以唯一 `round-36:` commit 提交。

## 可验证子任务

1. **开发服务器协议**：实现 Vite 8 Environment API `hotUpdate` 数据插件与安全路径分类，覆盖 data/MOD JSON 的新增、修改、删除，确保只广播自定义事件。
2. **客户端桥接与菜单接线**：建立开发态订阅/批处理/清理桥接；菜单收到变更后重新装配最新世界数据并更新当前视图。
3. **游戏运行态热重载**：从当前运行态捕获内存快照，场景在安全边界重启并经 `planSnapshotRestore` 预检，重建跨资源依赖族后恢复原位置与有效运行事实。
4. **专项验证、文档与提交**：测试插件和通知合并，实测 Vite 开发服务器文件变更事件，运行类型检查、生产构建及相邻轮回归，补齐资料作者工作流和提交。

## 风险

- Vite 的 public 资料文件默认会触发整页刷新；插件必须使用当前 Environment API 的 `hotUpdate` 并返回空模块列表，专项验证确认自定义事件生效且浏览器不 reload。
- 世界资料有跨资源引用，局部替换会留下旧索引；本轮通过共享世界加载器重新校验/组装，并以兼容预检决定是否恢复运行态。
- 删除地图、角色模板等资料可能令当前存档无效；安全失败需保留完整旧运行态到错误画面/主菜单，而不能留下半套新旧资料。
- 编辑器连续写入会短时多次触发事件；客户端合并通知并在无移动/战斗/覆盖 UI 时处理，避免场景销毁中断事务。
- 浏览器/生产模式没有 Vite HMR 通道；生产构建将确认相应逻辑被剔除，手动验收只针对 `npm run dev`。
