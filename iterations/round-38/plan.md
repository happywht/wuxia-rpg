# Round 38 计划：建立 Vitest 测试基线

## 本轮目标

为当前数据驱动引擎建立可重复运行的自动化测试基线，覆盖基础资料 Schema 校验、事件总线、对话解析/运行时条件与任务状态流转；保留现有 CLI 校验行为，并让失败案例能被测试定位。

## 用户故事

- 作为开发者，我希望用统一命令运行自动化测试，以便在迭代引擎时尽早发现回归。
- 作为内容作者，我希望测试实际调用生产资料校验流程，并能证明无效资料会被拒绝。
- 作为系统设计者，我希望对话条件、任务进度和事件订阅的关键规则有可读测试，避免后续扩展破坏现有行为。

## 验收标准

1. 使用 Vitest 建立配置与 `npm test` 命令；测试文件被 TypeScript 严格检查。
2. 至少覆盖事件总线的订阅/退订/once 重入语义、对话解析及条件可见性、任务接受与目标推进、实际基础资料 Schema 校验。
3. `npm run validate:data` 的命令行输出及失败退出语义继续有效，测试复用其可导入校验逻辑而不重复实现规则。
4. 更新测试说明及 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`，记录实际验证命令和结果。
5. `npm test`、`npm run typecheck`、`npm run validate:data` 及至少一项既有烟测通过；`git diff --check` 无空白错误。
6. 本轮改动独立提交，提交信息以 `round-38:` 开头。

## 子任务

1. 建立 Vitest 依赖、配置、脚本和测试类型检查范围；抽取基础数据校验器为可复用模块，同时保持 CLI 入口。
2. 为纯引擎模块和数据校验器编写正反向单元测试，覆盖边界语义而不依赖 Phaser 场景。
3. 运行测试、类型检查、资料校验和回归烟测；补齐测试文档、日志与路线图，再提交。

## 涉及文件

- `package.json`、`package-lock.json`、`tsconfig.json`、新增 `vitest.config.ts`
- `.gitignore`（忽略测试工具生成的本地缓存）
- `scripts/validate-data.mjs`、必要时新增 `src/engine/data-validation.ts`
- 新增 `tests/` 下事件总线、对话、任务和资料校验测试
- 新增或更新 `docs/TESTING.md`
- `docs/ADR.md`、`docs/REFERENCES.md`（核验 Vitest 版本兼容性并登记精确版本/许可来源）
- `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`

## 风险

- Vite 主配置含异步 HMR 插件，测试运行器应避免启动开发服务器并保持配置隔离。
- 资料校验脚本目前在模块顶层执行；抽取时需维持 CLI 调用兼容并让测试能安全导入。
- 测试不得依赖外部网络、时钟或共享可变状态，避免产生不稳定结果。

## 预计人类工程师工时

约 2–3 小时；至少包含配置接入、可复用校验路径、引擎测试、回归验证和文档更新。
