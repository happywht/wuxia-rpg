# Round 42 计划：雾渡主线章节与结局衔接

## 本轮目标

在 R31「渡籍补录」之后增加一段原创、可实际游玩的主线章节：玩家沿着旧渡籍的水痕与多方证词查明一页被改写的轮值记录，经过「旧簿验痕 → 两家对页 → 封存水痕」，再在「明册立约 / 护证留印」之间作出互斥选择，分别抵达「公簿昭潮 / 灯下留痕」数据结局。复用现有任务、条件对白、知识图谱、物品和结局协议，不把人物或剧情写入引擎代码。

## 用户故事

- 作为已完成渡籍补录的玩家，我希望能从已有药道故事继续追查文书疑点，而不是只看到互不相连的支线清单。
- 作为做出不同决定的玩家，我希望公开查证或保护证人会记录为不同见闻、完成不同任务并抵达相应结局，且能在百科中追溯证据关系。
- 作为资料作者，我希望通过任务前置、对白条件/效果与图谱关系描述完整章节，沿用既有 Schema 和 MOD 覆盖流程。

## 验收标准

1. 计划先于实现；新增 3 个线性任务和 2 个共前置互斥分支，章节前置来自 `quest.r31-ferry-ledger`，章节末端分别通向新的公开记档/护证结局。
2. 在现有 NPC 对话图上接入全部接取、交付和分支节点；任务状态变化、对白效果、证物入包、证词发现及分支互斥均使用现有通用协议；不存在重复 conversation id 或悬空节点/跨资源引用。
3. 新证物通过对白原子授予并作为第三段任务目标，完成任务链不要求特定门派；证物不可出售且不进入商店。分支任务共用精确一致的前置集合，接取其一会使另一条失败。
4. 新增任务、证物、事件和结局在图谱中有正确 kind、发现状态与 `participatesIn`/`requires`/`holds`/`influences` 等有效关系；图谱计数按实际资料更新。
5. 新增 Round 42 专项可重复烟测，核验章节结构、互斥/结局条件、对话图引用和图谱边；更新任务志、结局志、知识图谱说明，以及 CHANGELOG、DEVLOG、ROADMAP 和本计划实施记录。
6. 运行专项烟测、`npm run check`、`npm run build`、Round 27/31/33 回归 smoke 与 `git diff --check`，记录真实结果并提交唯一 `round-42:` commit。

## 子任务

1. **章节与因果设计**：确认 R31 接续条件；建立「旧簿验痕 → 两家对页 → 封存水痕」3 个共通阶段、「明册立约 / 护证留印」2 个互斥处理路线、新证物和「公簿昭潮 / 灯下留痕」两条结局；为每个可判定剧情事实设计图谱节点/边。
2. **资料接线**：扩展任务、物品、白鹭洲/柳听澜/顾夜尘/祝九弦四人的对话图、图谱和结局资料，校对选项可见时序、授予/取证效果与通用运行时边界。

## 风险

- NPC 对话信号在打开对白面板前结算；新章节用此顺序即时解锁后续任务，必须检查选择条件重算时序。
- 对话资源重复 id 按首个声明胜出；本轮须扩展 NPC 已引用的既有图，而不能以第二份同 id 对话静默覆盖。
- 分支两项必须同组且有相同前置；对白效果按事务执行，避免选择已失败分支或半提交社会状态。
- 新增结局要求同时满足任务状态与已发现图谱节点；必须设计能在目标支线完成时显式解锁证据的对白，不能出现名义可达、实则无途径的锁定结局。
- 仅依赖现有地图和人物，不加新地图/硬编码剧情引擎能力；物理手柄测试不在本轮范围。
