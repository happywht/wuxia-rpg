# Round 44 计划：日程驱动的渡口争议与门派声望

## 本轮目标

把 Round 43 的漫游奇遇扩展为真正受 NPC 日程影响、并对玩家门派声望产生一次性后果的江湖事件。玩家在黄昏、湿天气、已读风雨传函，且按时出现的石北与白鹭洲同时在身边时，有机会遇见渡口系缆桩争议；随后选择先加固旧桩或先据渡簿复核，以互斥差事完成选择并取得对应门派声望与百科见闻。所有事件条件、任务目标、奖励和叙事仍由资料声明。

## 用户故事

- 作为探索者，我希望能在正确时辰遇见正在按日程活动的 NPC，而不是只因自己经过固定地点就凭空触发江湖事件。
- 作为调停者，我希望面对两种有依据的处理方式，并在完成选择后看到门派对我做法的实际评价。
- 作为资料作者，我希望事件能声明必须在场的人物，任务能声明声望与见闻奖励；坏跨资源引用应有诊断并隔离，不破坏其余世界内容。

## 验收标准

1. 区域事件条件可声明 `nearbyNpcIds`；运行时只把当前地图上、按现实时段日程落位且与玩家四向相邻的人物计为在场。固定事件与漫游事件都使用同一条件语义。
2. 世界图解析器和 Schema 校验附近人物列表；装配器依据 NPC 资料验证引用，坏人物引用只禁用对应事件并给出 warning。缺少该字段的旧世界图行为完全不变。
3. 新的漫游争议只在成功走格后尝试，并要求风雨传函见闻、黄昏、湿天气及石北/白鹭洲同时在场；移动时间推进后的 NPC 日程先更新再判定，等待/读档/传送不抽签。
4. 任务奖励协议兼容旧 `experience`/`currency` 字段，并可声明门派声望变化及结算后发现的图谱节点；任务状态机只在首次进入 `completed` 时发奖励，坏门派/节点引用隔离对应任务。
5. 新增两项共享事件前置与互斥组的调停差事，分别以接触石北或柳听澜完成；仅完成所选差事后发放对应门派声望、百科见闻和 UI 反馈。任务名录可预览门派声望报酬。
6. 知识图谱、任务志、地图图册、测试文档及项目文档准确反映本轮数据；新增集成测试覆盖日程/邻接、坏引用、分支互斥、声望钳制与一次性奖励。
7. `npm run check`、`npm run build`、Round 30/31/33/43/44 专项回归及 `git diff --check` 全部通过；以单个 `round-44:` commit 提交。

## 可验证子任务

1. **事件与日程联动协议**：增加附近 NPC 条件的 Schema、parser、装配引用校验及 GridScene live context；用 NPC 日程纯数据测试证明黄昏相邻成立、离场/换时段不成立。
2. **任务声望与见闻结算**：扩展任务奖励资料、解析、引用校验、状态机 reward grant、社会状态/百科提交及任务面板提示；验证合法边界、坏引用、完成一次与重复信号不重复发奖。
3. **渡口事件与玩家抉择**：加入事件、互斥差事、对白、图谱节点/关系和资料；用跨模块集成用例分别完成两个分支并验证仅一边增加声望及解锁结果。
4. **审计、文档和收尾**：更新 `audit:round-34` 相关文档断言、日志/路线图，运行完整门槛、专项烟测、生产构建与差异检查，再提交。

## 风险

- 触发条件要读取 `advanceTime` 后已更新的日程布置；必须在成功步移动的结算边界计算邻接，不把 NPC 补间动画误当逻辑坐标。
- 随机事件可以在符合条件的连续移动中重试；一旦发现即沿用现有一次性存档集合，避免读档或等待重复结算。
- 声望和见闻奖励必须与任务完成状态一起只结算一次；任务取消/失败不能先行给奖励。旧任务奖励缺省新字段必须稳定解析。
- 地图装配早于 NPC 最终放置；事件人物引用校验需要使用最终覆盖层 NPC 资料 id 清单，同时运行时只能匹配通过装配并按日程落位的 NPC。
