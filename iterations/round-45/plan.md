# Round 45 计划：战斗、成长、经济与制作数值平衡

## 本轮目标

核对现有战斗成长与货币来源，修复擂台重复夺魁反复发放银两和物品的经济灌注；保留逐场战斗经验作为 30 级成长所需的重复训练来源，保留擂台重赛和战绩，并把数值基线及设计边界写入文档。

## 用户故事

- 作为反复参加切磋的玩家，我可以通过真实胜利继续获得战斗经验、重赛提升战绩，但同一擂台的银两和物品彩头只在首次完整夺魁时领取。
- 作为首次报名的玩家，我在能收下首夺彩头时才受背包/钱袋限制；已经领过彩头后，整理背包不再阻止纯战绩重赛。
- 作为资料作者/维护者，我可以从测试和文档看清现有经验曲线、一次性剧情经验及擂台的结算口径，并获得可复现的回归检查。

## 验收标准

- 每场擂台胜利仍通过通用战斗协议发放该轮数据经验；首夺彩头仅含配置的货币与物品。
- 只有从未夺魁且本次完整连胜时，才发一次配置的货币与物品；失败/半程不发彩头。
- 首夺后重赛仍增加 `attempts`、`bestWins`、`lastWins`、`championships`，并按真实战斗胜利获得经验，但不再发货币/物品。
- 首夺状态复用存档已有的 `championships` 记录，不增改 v1 存档格式；已夺魁旧档视为彩头已领。
- 新增 Phaser-free 自动化回归，覆盖首夺、失败/半程与重赛奖品边界、每轮经验保留，以及实际擂台数据的奖励汇总。
- 新增平衡审计文档，写出可复算的经验/奖励基线、擂台重复结算前后差异、公式与尚未模拟的因素；同步擂台玩法文档、CHANGELOG、DEVLOG、ROADMAP。
- `npm run check`、生产 `npm run build`、擂台/战斗相关专项测试和 `git diff --check` 通过；提交为一个 `round-45: ...` commit。

## 子任务（各自可验证）

1. **战斗/经验结算**：验证擂台各轮继续复用普通战斗经验规则，避免截断成长；用纯逻辑单元测试覆盖每轮经验与首次、未完成、已夺魁重赛彩头。
2. **经济/存档边界**：仅首夺奖励需要预留货币上限和背包容量；重赛只计战绩；覆盖旧存档的 `championships` 语义与奖品资源汇总测试。
3. **数值说明与整体回归**：记录当前剧情任务、固定遭遇、擂台与主要价格/配方的审计基线及其局限，更新开发日志/路线图并运行全量检查与构建。

## 风险

- 失败尝试仍会获得已胜各场的战斗经验；报名面板必须明确首次夺魁现金/物品彩头，避免重赛不再发奖显得像结算故障。
- 现有存档没有单独的奖励领取位；用已持久化的 `championships > 0` 判断首夺，可避免迁移，但无法恢复历史存档已经重复领取的银两。
- 静态经验总和不等于真实通关收益：任务存在互斥/失败条件，门派战和成就另有数据驱动奖励；文档必须标清统计范围。

## 预计人类工程师工时

约 60–90 分钟：规则与资源审计、引擎结算/UI 改动、单元测试、数值记录、完整回归与提交。
