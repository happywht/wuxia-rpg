# Round 46 计划

## 本轮目标

以仓库中的真实基础资料和现有引擎 API 建立可重复的纵向验收：从角色开局与地图移动，经过数据对白、任务、战斗/成长、物品和武学变化、存档恢复，继续验证 R42 两条互斥故事路线分别抵达对应结局。验收若暴露垂直切片中的真实断点，本轮修复并补回归。

## 用户故事

- 作为玩家，我从真实角色模板开始后，能在实际地图上遵守网格碰撞规则，与 NPC 交谈并由对白条件看到当前可做的任务选项。
- 作为玩家，我完成任务、战斗和奖励后，能获得资料定义的物品/成长/武学，并保存、读回后继续游玩。
- 作为资料作者，我希望对白、任务、物品、武学、战斗和结局之间的引用由基础资料贯通验收，而非只分别通过孤立单测。

## 验收标准

1. 新增 Phaser-free 集成回归，直接读取并解析现有基础角色、地图、对白、任务、物品、战斗、武学、存档及结局资料，不复制一套平行的故事 fixture。
2. 使用实际 `GridMap`、`DialogueSession`/对白条件与效果运行时、任务状态机和物品/成长/战斗模块，断言合法走格与阻挡、对白门控、接取/推进/完成及奖励结算。
3. 将代表性运行状态序列化并通过存档解析、恢复，再断言角色、背包、任务、社会/门派进度可继续驱动对话和任务。
4. 分别以实际对白效果和任务状态机推进 R42 两条互斥路线，证明同伴分支失败，且仅相应结局满足判定并可被选择。
5. 若验收发现引擎缺陷，本轮修复须增加针对性回归；更新测试指南、CHANGELOG、DEVLOG、ROADMAP，并记录真实命令、结果和局限；提交 `round-46:` commit。

## 可验证子任务

1. **真实资料纵向 harness**：装配测试所需的角色、地图、任务、NPC、对白、物品、遭遇和武学资料；验证开局、移动/碰撞、对白条件与任务接取。
2. **成长与续玩闭环**：驱动战斗胜利、物品和武学变化；经快照 JSON 往返与恢复后继续检查有效状态和对话/任务行为。
3. **双路线结局与缺陷修复**：经实际 R42 对白效果和任务信号分别完成公开登记、保护证人分支，检查排他失败和结局选择。
4. **质量门槛与文档提交**：运行专项集成、全量 `check`/生产构建及相邻回归；更新文档和项目日志，检查差异并提交。

## 涉及文件

- 新增：`iterations/round-46/plan.md`、`tests/round46-vertical-slice.test.ts`
- 视验收发现的实际缺陷调整：相关 `src/engine/` 模块或 `src/game/` 接线；必要时添加 `package.json` 的 R46 专项 smoke 命令
- 文档：`docs/TESTING.md`，以及本轮需要说明的任务/存档/结局文档
- 项目记录：`CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`

## 风险

- Phaser 场景输入/UI 不宜在 Node 单测中伪装成完整浏览器游玩；集成测试只声明实际调用的引擎/API 边界，必要时另做真实浏览器手测。
- R42 故事链依赖较早的渡籍任务与 NPC 互动；测试需通过真实对白效果和任务信号推进，避免重现现有测试直接改任务状态而绕过运行时的问题。
- 存档快照会对当前资料引用执行恢复预检；夹具必须来自同一套实际装配数据，避免把测试构造差异误判成游戏缺陷。

## 预计人类工程师工时

约 3–5 小时：资料/引擎接口装配与调查 45–75 分钟；主线纵向测试和必要修复 75–120 分钟；双分支、存档续玩与边界回归 45–75 分钟；文档、全量门槛与提交 30–45 分钟。
