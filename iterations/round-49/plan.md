# Round 49 计划：公测前反馈式验收与资料告警修复

## 本轮目标

进行一次可复现的公测前试玩检查，优先修复新游戏开局时 HUD 报出的默认可选资料告警；补上覆盖真实默认资料装配的回归检查，并记录一条可供后续试玩者使用的反馈模板与验证结果。当前没有外部试玩反馈来源，本轮只记录亲自复现的验收发现，不虚构玩家意见。

## 用户故事

- 作为第一次启动游戏的玩家，我希望默认内容能完整加载，不在开局就看到资料无效告警，也不会悄悄禁用 NPC、对话、成长、战斗、物品、商店或任务。
- 作为内容作者，我希望持续集成验证真实默认资料的 schema 与跨资源装配，尽早发现会导致运行时降级的问题。
- 作为试玩者，我希望能用简短统一的模板记录复现步骤、预期与实际结果，方便后续优先处理真实反馈。

## 验收标准

1. 从主菜单新建角色进入世界，默认数据加载不再显示“部分可选资料无效”的告警；新增自动回归检查能报告违规资源/装配诊断。
2. 回归检查从仓库实际 `data/` 读取 manifest、schema 和资源，至少断言可选资料装配无告警，不能只验证内联假数据。
3. 浏览器手测覆盖新游戏、网格移动/碰撞、NPC 对话或交互、任务、战斗或物品/武学中的至少三段主要闭环；另检查设置/存档入口且不覆盖已有存档。
4. 更新试玩反馈记录、`CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md` 及受影响的架构/内容文档；跑数据校验、类型检查、自动回归与完整测试/审计。
5. 以 `round-49: ...` 格式提交本轮所有计划、实现、验证记录和文档。

## 子任务（均可独立验证）

1. 读取真实默认资料并复现、定位启动告警来源；建立能给出具体诊断的回归基线。
2. 修复造成默认资料降级的源数据或装配问题，并验证 NPC、对话、任务、战斗、物品等内容重新可用。
3. 在浏览器继续走查新手纵向流程与存档入口，将可复现结果整理为试玩记录和反馈模板。
4. 更新路线图、变更日志、开发日志与相关指南，运行项目验证命令并形成 Round 49 提交。

- `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`

## 风险

- 默认资料告警可能来自有意配置的降级，而不是真实缺陷；先取得逐条诊断与装配证据，再决定修改，避免删除有意设计的内容。
- 浏览器试玩使用本地存储；开始前检查存档入口，只写入明确空槽，不覆盖已有槽位。
- 当前暂时不能取得真实外部试玩反馈，因此“反馈式验收”只代表本地可复现检查；文档会明确这点。

## 预计人类工程师工时

约 60–90 分钟，包含资料诊断、问题修复、回归覆盖、浏览器走查和文档整理。
