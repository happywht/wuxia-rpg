# Round 51 Plan — Large Scrolling World and Licensed Pixel Art

## 目标
将当前两张 16×9 的占位地图升级为约 100×100 格、可连续步行探索的江湖大地图。相机跟随玩家移动；M 键舆图显示真实世界地图并支持拖动平移与缩放。以 Kenney 官方 CC0 Roguelike/RPG 户外地图图集与附带的 100×100 五层 Tiled 示例地图替换地表色块，以同系列 Tiny Dungeon 16×16 人物图替换几何人形；保留 NPC、任务、战斗、区域事件、切图、时间和存档语义。

## 用户故事
- 作为玩家，我可以在连绵的道路、山林、水岸与聚落中行走，画面随人物移动，不再被限制在一屏地图。
- 作为玩家，我可以打开舆图查看当前的大世界位置，拖动地图、缩放细看，并通过标记辨认已知区域。
- 作为玩家，我希望玩家与 NPC 使用统一风格的真实像素素材，不再看到简单矩形拼成的人形或纯色方格。
- 作为内容作者，我可以通过数据指定地图瓦片的素材坐标与阻挡属性，而不改引擎代码。

## 验收标准
1. 起始地图至少 96×72 格，玩家可从中心起点走到相距至少 20 格的不同区域；相机边界限定于地图范围，玩家接近边缘时镜头停在边界。
2. 地图为 100×100 格，包含示例地图中的连通道路、树林、水岸和聚落多层图像；碰撞仍由独立网格数据控制。
3. 游戏地图由网站公开 CC0 像素素材构建；玩家、NPC、伙伴都使用素材图像，原 `createPixelPerson` 占位绘法从游戏世界渲染路径移除。
4. M 键舆图显示大地图地貌与当前区域标记，支持鼠标/触摸拖动、滚轮缩放、键盘方向键平移、Esc/M 关闭；旧任务与切区入口可辨认。
5. 官方来源、CC0 许可、文件清单与用途写入 `docs/REFERENCES.md`，素材包自带许可随资源分发；生产打包仍包含必需的静态素材。
6. 地图与世界图 schema 校验通过；既有任务、商店、NPC、战斗和存档回归通过；新增测试覆盖大地图、素材元数据、地图视口导航。
7. 按轮次约定更新路线图、变更日志、开发日志、地图文档，执行 Round51 commit。

## 子任务（均需可验证）
1. **官方像素素材选型与接入**（约 20–30 分钟）：下载 Kenney Roguelike/RPG 与 Tiny Dungeon 官方 CC0 包，核对许可、16×16 图集间距和 Tiled 元数据；只添加实际使用的图集与原始许可，更新生产白名单和引用清单。以图像尺寸/资源元数据检查和打包审计验证。
2. **大地图与跟随相机**（约 30–45 分钟）：扩展数据协议以读取 Tiled 帧图层；转换为连通 100×100 地图；按素材图生成低分辨率缓存地表；配置地图边界与玩家跟随相机，并兼容现有区域切换和固定 HUD。以 schema、解析、边界与移动相关回归及浏览器实玩验证。
3. **角色精灵与可移动舆图**（约 25–35 分钟）：接入人物帧；舆图渲染世界瓦片缩略图、位置标记和现有区域信息；实现拖动/缩放/方向键平移，补充控件文档与输入状态回归。以 UI 手动操作和新增纯逻辑测试验证。
4. **整合与文档交付**（约 20–30 分钟）：跑数据检查、类型检查、全量测试、构建与发布 smoke；修正回归；更新地图图册、参考资料、路线图及三份轮次日志并提交。

## 风险
- 扩大地图后 HUD/面板不得随相机滚动；世界对象与界面对象需明确区分滚动因子。
- 户外图集和人物图集来自 Kenney 两个系列包；均为 16×16 像素并有明确 CC0 标示，但投影与轮廓仍需在游戏实景中检查；不把整包无用素材加入发行包。
- 单个巨型 canvas 易占用显存；以原生 16×16 像素生成地表纹理再最近邻放大，控制内存并维持像素锐利。
- 现有地图资源 ID 被 NPC、任务、地图事件和存档位置引用；保留 ID 与既有坐标语义，优先在原起始地图资源上扩建。
- 新地图相机可能影响现存 viewport UI / 自动化选择器；用浏览器实玩和全套回归发现并修正。
