# Round 52 Plan — 起始聚落辨识度与大地图寻路

## 本轮目标
修复起始地图像素地层被当作固定 HUD 留在地图左上角、未按相机坐标滚动的问题，让玩家实际走到哪里就看到哪里；用 Kenney 公开底图正确呈现开局聚落/道路，并能在百格大地图里辨认聚落、池塘与渡口方向。放大舆图时内容仍严格裁切在视窗内，开局交互与视觉地点相互对应。

## 用户故事
- 作为新玩家，我进入江南道时希望出生在一个有房舍、道路和人物活动的地方，而不是离聚落较远的空旷草地。
- 作为探索者，我能在 M 舆图上认出已登记的聚落、池塘与渡口方向，并准确判断它们相对当前位置的距离。
- 作为玩家，我放大舆图查看地貌时，地图不会压住标题、图例或其他界面内容。
- 作为内容作者，我可以在世界地图资料中增删标记点，而不在引擎里硬编码专名或坐标。

## 验收标准
1. 起始地图的每一视觉层都随玩家相机按相同世界坐标滚动；出生点在实际画面中能看到 Kenney 底图的聚落/道路，而非地图左上角草地。若需要校准出生点，玩家、七名起始 NPC、巷战、擂台、事件及其日程位置均通过真实地图可走性、无重叠校验。
2. 世界地图资料支持经过 JSON Schema 与语义校验的地标列表；M 舆图按地图资源筛选并画出当前位置及资料驱动的地标标记/图例，不写死人物、地名或剧情文本。
3. 放大舆图在最小/最大缩放和四边拖动下都裁切在既定视窗内；用独立小视口相机隔离地图图层，避免 WebGL 几何遮罩警告或溢出；滚轮只在地图视窗上缩放，关闭面板后不残留输入监听。
4. 新增纯逻辑回归覆盖地标资料解析/坏引用隔离与视口约束；运行真实资料校验、严格类型检查、全量测试、文档审计、生产构建和带地图素材的发布 smoke。
5. 浏览器手测新游戏开局聚落/道路/NPC 视野与玩家走格相机跟随；依据原 TMX/碰撞图审计不移动现有 NPC/巷战占格；M 舆图拖动到一个远端地标，核对标记/底图/坐标侧栏对应，再验证滚轮缩放、四边钳制、最小/最大倍率、关闭返回；结果记入开发日志。
6. 更新 GDD、地图图册、玩家指南、测试说明、路线图、变更日志和开发日志；以 `round-52: ...` 提交本轮。

## 子任务（均需可验证）
1. **地图地层相机滚动与开局核验**（约 20–30 分钟）：检查 R51 的全局 ADDED_TO_SCENE 固定 HUD 处理与地图贴图父子对象；显式确保大地图地层和旧图色块层随相机滚动。浏览器比对开局坐标实景与 TMX 地貌，若聚落仍不可见再调整初始人物/出生位置；检查实际可走性和占格。
2. **数据驱动地标与舆图图例**（约 30–45 分钟）：为世界地图添加通用 landmark 资料/schema/装配校验；绘制当地图标与玩家点的空间对应关系和侧栏说明；自动测试坏引用与地图筛选，不将专名或点位写入引擎。
3. **高倍率视窗裁切与输入边界**（约 15–25 分钟）：验证 Phaser/WebGL 几何遮罩限制；若遮罩无法裁切则改用独立小视口相机；校验最大倍率和四边拖动；确认离开舆图输入焦点后场景状态未残留。
4. **浏览器回归、文档与提交**（约 25–35 分钟）：跑 schema/占位/故事回归、全量 `check`、生产发布与带素材静态 smoke；记录首次启动及从聚落到渡口方向的操作验证，更新全部轮次日志并提交。

## 风险
- 出生点调整会影响事件、巷战、擂台、商店/NPC 日程和旧存档位置恢复；地图资源 ID 保持不变，所有静态与语义坐标引用须一起验证。
- Kenney 原 TMX 的地图标记仅按图层判断，不假设不存在的地名/用途；对不清楚的建筑使用描述性地标名，并由数据作者标记。
- Phaser 固定 HUD 与跟随相机处于不同坐标系；舆图必须拥有独立裁切视口，拖拽/滚轮坐标仍按主相机的屏幕坐标计算。
- 地标资料需保持旧世界图和同名 MOD 文件兼容，坏单项隔离并给出诊断，不能使世界整体无法启动。
