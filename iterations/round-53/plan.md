# Round 53 计划 — 地标寻路与区域探索反馈

## 本轮目标
把 R52 的可拖动舆图升级为实际可用的探索导航：玩家能从舆图选择已知地标或跨区关口，看到绕开阻挡地形的步行路线和距离；有知识门槛的地点在发现前不显示名字、类别、坐标或地图标记；抵达关口时舆图能说明其连接区域。

## 用户故事
- 作为行旅者，我能从舆图选中一个已经听闻的地点，看见避开湖泊、房舍等实心格的逐格路线，并按提示自行走过去。
- 作为探索者，我不会在发现某个地点之前从地图或侧栏看到它的名字、坐标和类别；完成对应见闻后再能查看和导航。
- 作为跨区旅行者，我能选中已登记的出入口，查看走到出入口的距离及它通向的区域，并继续使用现有步行切区机制。
- 作为内容作者，我能在世界地图资料里声明地标的发现见闻门槛；路径和可见规则由通用引擎解释，不在渲染代码写死地点或剧情。

## 验收标准
1. 新增 Phaser-free 网格路径算法，按地图阻挡格提供可复现的最短四向路线；不可达或越界目标给出明确空结果，不尝试穿墙。
2. 舆图可选择可见地标及关口，显示从当前坐标出发的路线、格数、方向分段和跨区目的地；关闭重开清空旧选择，步行后重新选择会按新坐标重算路线。
3. 地标可选 `discoveryNodeId` 门槛；未拥有该见闻时，地标的名称、类别、坐标、标记、计数均不进入 UI，已知状态才完整显示；引用坏掉的门槛按数据装配规则隔离并告警。
4. 默认资料至少把一个已有剧情地点设为见闻门控，验证发现前后地图均无/有对应信息，且其余现有无门槛地图和旧 MOD 文件保持兼容。
5. 新增路径、资料装配和发现门控测试；运行数据校验、类型检查、全量测试、质量门槛、浏览器舆图显示核对及发布构建。路径/发现逻辑由自动测试覆盖；若浏览器自动化无法可靠操作地图控件，需如实记录路线 UI 点选未核验。
6. 更新地图/玩家指南、路线图、变更日志和开发日志，记录命令与浏览器操作；完成 Round 53 专属 commit。

## 子任务（均需可验证）
1. **网格寻路与目标适配**（约 25–35 分钟）：实现确定性 BFS/A* 纯逻辑模块，支持可行格目标及地标实心格周边可达停靠格选择；用路线最短、绕障、不可达、边界和稳定并列路径用例验证。
2. **地标发现门控与引用校验**（约 20–30 分钟）：扩展世界图 Schema/parser/assembly 的可选见闻引用；现有芦苇河滩探索见闻用于默认资料门控；测坏引用隔离和旧资料兼容。
3. **舆图 waypoint 交互与跨区提示**（约 30–45 分钟）：添加地标/关口列表与点选，绘制选中路线，显示步数、方向分段和通向区域；仅向面板传入已知见闻集合，验证选择重置与面板生命周期。
4. **整合回归和玩家说明**（约 25–35 分钟）：跑数据/typecheck/全测/check/发布包；浏览器操作从当前位置选渡口导航并验证芦岸地点发现前后可见性；修正文献总述与已打包 CC0 图片清单矛盾；更新文档、日志并提交。

## 风险
- 现有部分地标坐落在水面或建筑阻挡格，必须为其选取最近的可达邻接停靠点，不能把标记位置误当成可走格。
- 见闻门控需贯穿解析、装配和渲染筛选，防止侧栏计数/类别等旁路泄露；坏引用不得让整张地图无法加载。
- 地图最多 256×256，纯逻辑寻路应限制/优化搜索并保持每次移动更新路线的成本可控。
- 关口只有在与玩家相邻时由既有系统切区；舆图只负责提供路线和目的区域信息，不能造成瞬移或跳过既有条件。

## 执行中计划调整

- 首次 CUA 浏览器验证能进入新游戏并打开地图，但鼠标点舆图侧栏时面板会收起，无法可靠观察路线 UI 的选中状态；为避免把自动化工具现象记成 UI 已通过，最终验收以浏览器确认地图/已知列表能显示、纯逻辑测试确认路径和见闻投影为准，并将实际 UI 选点复核列为 R54 风险项。
