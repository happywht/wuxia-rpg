# Round 54 计划 — 跨区域舆图导航与 waypoint 操作闭环

## 本轮目标

让玩家能可靠地从舆图选择地图标记，并把当前 100×100 起始区与雾雨渡口连成可规划的区域旅行路线：远区目的地显示区域路径，同时给出当前区域应走向的下一个关口及本地碰撞避让路线。导航继续由玩家步行执行，不通过地图瞬移。

## 用户故事

- 作为行旅者，我点击侧栏地点或地图标记后，舆图保持打开、明确高亮目的地，并立即看到步行距离和方向提示；我也能用键盘选择，不依赖精确鼠标命中。
- 作为跨区旅行者，我能从当前区域规划到另一区域已知地点，看到途经区域和下一道需实际走到的关口；进入新区域后能继续查看剩余路线。
- 作为探索者，我不能从跨区候选列表得知尚未发现的地点名称、门类或所在区域；对应见闻达成后才可规划到它。
- 作为资料作者，我只需声明地图区域、地标和有向关口连接，引擎即可计算区域级最短旅行路线。

## 验收标准

1. 浏览器实测点击至少一个列表 waypoint 与地图 pin 都能选中路线，面板不收起；键盘循环选择并确认同样有效；关闭重开清除选择。
2. Phaser-free 世界旅行算法在有向 transitions 图上返回确定性最短区域路径；目标不可达、端点无效时返回可读失败，不虚构关口或瞬移。
3. 选择远区已知地标后，面板显示终点和途经区域，并用当前地图碰撞格寻路到第一道有效关口；本区目标仍显示直达路线。
4. 未发现地标不会以远区目的地候选暴露其 id、名称、类别或地标所在区域；发现后该目的地可选。已在世界资料中公开声明的可见关口仍显示其直接连接区域名，因为这是玩家可用的关口信息。
5. 覆盖方向不对称连接、多关口最短路/稳定并列、不可达、未知地点隔离、第二张真实地图关口路径与列表/键盘选择逻辑的自动回归。
6. 浏览器完成本区标记选点、远区目的地行程提示和面板生命周期核对；运行数据校验、类型检查、全量质量门槛、生产包构建/子路径 smoke；更新玩家指南、地图/架构说明、路线图、变更/开发日志并提交专属 Round 54 commit。

## 子任务（均需可验证）

1. **输入命中诊断与选择交互修复**（约 25–40 分钟）：追踪 Phaser 多相机/UI 输入事件；修复鼠标点选关闭舆图或选中状态无反馈的问题；增加可键盘循环的 waypoint 焦点与确认操作，并以输入状态逻辑/场景辅助测试覆盖 selection、route clear 和 close 生命周期。
2. **跨区域旅行图算法**（约 25–35 分钟）：从已装配 regions/transitions 建立有向邻接关系，以 BFS 找到稳定最短的关口序列；校验孤岛、回程单向边、重复目标和坏端点。
3. **远区目的地接入舆图**（约 30–45 分钟）：将已知远区地标加入候选，在选中时把区域序列投影为“终点—途经区域—下一关口—本区路径”；已知门槛贯彻整个投影，不跨地图使用错误坐标。
4. **浏览器/资料回归与交付**（约 25–40 分钟）：实测鼠标与键盘操作、远区提示、打开关闭和步行切区后的继续导航；运行全量检查/发行烟测、更新说明并提交。

## 风险

- Phaser 的地图专用 camera 与主 UI camera 同时参与渲染/命中测试，输入对象层级和 pointer 坐标可能与显示状态不一致；需在真实浏览器验证，而非只凭纯逻辑测试推断。
- 目前只有两块尺寸差异很大的地图。世界级规划只能返回逻辑区域/关口链，并需把第一段路线限制在当前地图坐标系；本轮不伪装成统一连续 tilemap。
- 航路是有向资料边；回程须有反向 transition，不能把单向关口自动视作双向。
- 未发现区域地标的隐私门槛应优先于世界路径渲染和摘要计数，避免跨区 UI 泄漏地点情报。
