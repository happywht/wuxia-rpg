# Round 55 计划 — 扩建第二块百格区域与跨区步行闭环

## 本轮目标

把雾雨渡口从 16×9 测试小场景扩建为独立的 100×100 可步行大型区域，使用仓库已有 Kenney CC0 户外像素 tileset 构建与江南道有明显区别的河湾、渡镇、山林和旧水道地貌；保留现有数据驱动关口、角色、地标、固定/漫游事件及见闻内容，并让玩家能从江南道步行抵达渡口后继续游览、再由原有关口走回。

## 用户故事

- 作为跨区旅人，我从江南道实际走至石阶渡口并按 E 后，会落在雾雨渡口的码头边；这里不再是只有数步的过场小图，而是能跟随镜头探索的另一片大地图。
- 作为探索者，我能在河湾周边看见由道路、岸线、树丛、建筑和旧水道构成的多层像素地貌，地图标记与可行走网格一致，并能走到主要区域及回程关口。
- 作为既有存档玩家，原来渡口脚印、芦岸寻迹、NPC 日程、地图地标和返回江南道的落点仍可工作；新增地图内容继续由独立资料声明，不硬编码进引擎。
- 作为资料作者，我能从确定性生成脚本重建第二张地图，并在基础数据 Schema 与语义校验中发现尺寸不一致、阻挡关口或断路。

## 验收标准

1. `map.round-10-mist-ferry` 为 100×100，地图网格、每个像素艺术图层和 Schema 维度一致；有效可行格数显著高于原 144 格，出生点和所有保留玩法坐标均为可达格。
2. 通过已有许可的 Kenney CC0 素材和多个数据图层呈现独特河湾地貌；保留原始许可来源，不新增未授权素材，也不把素材/剧情写入引擎代码。
3. 原有江南道→渡口与渡口→江南道有向关口的精确格可达，出入落点、初到脚印与 5,4 的条件见闻点均有效；渡口已有 NPC 日程点与地标坐标仍在合法可达地面。
4. 自动质量检查覆盖地图尺寸/图层/碰撞、关口端点 BFS 可达、固定事件和现有 NPC 位置可达，并能验证两区域间实际两向转换使用不同地图坐标系；至少一个新增渡口远景地标在地图舆图中正确定位。
5. 浏览器人工试玩从江南道步行到石阶渡口、按 E 抵达百格雾雨渡口、探索并规划本区地标、再走回程关口返回江南道；记录实际验证边界。
6. 更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md` 和地图/玩家/架构/资料说明；运行数据与 MOD 校验、类型检查、专项/全量测试、生产打包及非根路径 smoke，并独立提交 `round-55: 扩建雾雨渡口百格地图`。

## 子任务（均需可验证）

1. **现状坐标/许可/地形审计**（约 25–35 分钟）：汇总渡口事件、地标、关口、所有 NPC 日程与固定遭遇坐标；分析已授权 Kenney 户外图集可用地表/岸线/道路/建筑/树丛 tile；明确落点保护区并写成生成器约束。
2. **百格渡口资料生成与可玩地貌**（约 45–60 分钟）：新增可重复的 Round55 地图生成脚本，生成 100×100 碰撞网格和多层 Kenney 图块；建设贯穿不同地貌的主路、河湾与支路；将主要出入口、旧脚印河滩、聚落和新增探索地标放在可达空地。
3. **语义可达性与跨图连续体验**（约 35–50 分钟）：增加针对扩建地图的回归测试和必要语义校验，证明保留关口/事件/日程坐标连通且方向入口不被地貌堵死；运行浏览器往返试玩并修复发现的问题。
4. **整合、文档和发布验证**（约 30–45 分钟）：更新数据指南、舆图说明、玩家操作指引、路线图和开发日志；跑完整质量门槛/生产发行包 smoke；核对变更并单独提交 Round 55。

## 风险

- 地图尺寸扩张会明显放大 JSON 与初次地图绘制工作量；应复用已发布 CC0 图集、共享纹理和稀疏覆盖层，避免复制或生成大量重复装饰。
- 碰撞是独立网格，不能仅凭贴图猜测；河面、树墙、建筑屋顶与视觉岸线必须和资料碰撞一致，并给玩家留出明确通路。
- 扩图不能移动旧存档正在进行的见闻/事件/NPC 日程落点，也不能堵住单向声明的任一转换格；转换验证须按各自地图的坐标检查。
- 浏览器可交互视口小于 100×100 世界，需通过真实游走和舆图检查镜头边缘/关口；单纯验证 Schema 或 grid BFS 不足以证明体验完成。
- 新地标需使用现有语义类别与世界数据 Schema；如需新增知识图谱关联，需连同节点、边和文档一起修改。
