# Round 60 — 差事目标导航与跑图提示

## 本轮目标

让玩家从 Q 差事日志直接把进行中的差事目标设为舆图行路目标，并在跨区行路、地图目标提示与 NPC 日程变化时保持提示准确。沿用 Round 57–59 已交付的大地图与无传送导航，不改动存档格式，也不把剧情坐标写入引擎。

## 用户故事

- 作为接下差事的玩家，我希望从任务日志一键导航到下一项未完成且有地图位置的目标，避免只看文字后在大地图中盲找。
- 作为正在寻找人物或遭遇的玩家，我希望路线随时段 NPC 日程变化而更新，并能看见跨区域下一道关口。
- 作为仅有采集目标的玩家，我希望任务日志明确说明该目标没有地图标点，避免误以为导航失效。

## 验收标准

1. Q 日志对进行中的差事显示 N 导航；按下后自动跟踪该差事、打开舆图并选择下一个未完成的空间目标。
2. 空间目标由通用数据关系解析：人物对话目标指向人物当前时段位置，战斗目标指向遭遇位置，见闻目标指向触发该知识节点的地图事件/地标。
3. 导航复用现有寻路与跨区域关口流程；关闭/重开 M 舆图后目标仍在本次运行中有效。NPC 位置变更时重新解析路线。
4. 只对已接取的活动差事投影目标；不得从锁定/未接任务泄露隐藏地点。采集目标不伪造地图坐标，找不到空间目标时显示清晰提示。
5. Phaser-free 单元测试覆盖活动状态过滤、多目标优先级/进度跳过、NPC 时段位置、遭遇/见闻目标与无空间目标；类型检查、数据校验、全量测试和发布包烟测通过。
6. 更新玩家手册与 R60 开发记录、变更日志、路线图，并记录验证命令与结果。

## 子任务

1. 建立可测试的任务空间目标解析器，使用当前有效任务进度、已装配人物/遭遇和世界图事件/地标解析稳定目标，不在引擎里写具体角色、地点或剧情。
2. 将 Q 日志快捷导航接入现有运行期目的地，并让 M 舆图显示/选择任务目标；保持 NPC 时段位置与已有跨区路线一致。
3. 补充解析器与 UI/路线集成覆盖，更新玩家操作说明及项目迭代文档，运行完整验证并修复发现的问题。

## 风险

- 寻找人物时若使用静态基础坐标会与日程位置错开；每次绘制导航提示时应基于当前时段重新解析，并优先采用当前地图实际布置位置。
- 发现目标通常在百科获知前隐藏；仅对已接取并仍活动的任务临时投影任务目标，完成后恢复常规发现规则。
- 舆图已有地标 ID 与临时差事目标 ID 共用字符串接口；目标 ID 必须命名空间隔离，且不得写入存档。
- 若地图事件或 NPC/遭遇数据缺失，解析器需返回无可导航目标并给可读提示，不得破坏任务接取与进度。

## 预计人类工程师工时

约 60–90 分钟：纯逻辑与测试约 25 分钟，面板/舆图/场景接线约 25 分钟，端到端验证、修复与文档约 20–40 分钟。
