# Round 61 — 差事导航抵达操作提示与路线审计

## 本轮目标

玩家按 R60 的差事导航到达人物、遭遇或见闻目标后，HUD 应说明下一步对应的操作；导航路径还须避开当前时段占格的人物与尚存遭遇，确保提示路线可实际走通。同时以当前真实地图、人物日程和差事目标核算 R58 六项差事的区域内跑图距离；若审计发现任务发布人或目标无法从地图入口到达，修复对应数据放置并加回归锁定。修正玩家手册中可能含糊的导航说明。保持引擎不含具体剧情资料，不改存档格式。

## 用户故事

- 作为按差事导航赶路的玩家，我希望抵达目标旁后能直接看到应按的键，避免到点后仍要猜该按 F 还是 E。
- 作为正在评估区域任务路线的制作人员，我希望能根据当前地图和人物日程复算六项差事目标的步行距离，判断路线提示是否遗漏跨区或日程信息。

## 验收标准

1. 任务导航抵达人物、遭遇、见闻目标时分别显示与现有交互规则一致的下一步提示；目标进度完成前保留差事导航，目标推进后继续指向下一空间目标。
2. 地标与差事路径均避开当期人物及活动遭遇的占格；NPC 换时段、遭遇结束或抵达目标变化后重算路径。
3. 若唯因动态占位而暂时无路，保留所选目的地并在 HUD 说明等待通路变化；日程/遭遇变化后自动重算。排除占位后仍无地形路线的目标保持既有无路处理。
4. 跨区关口提示、失效目标和无路提示保持原语义；静态 UI 不包含具体人物/地点/任务名。
5. 自动化路线审计读取经 Schema 校验的实际基础资料，覆盖 R58 六项任务、七个 NPC 日程时段下从对应地图入口到发布人及目标的步行距离和目标停靠格；任务发布人和空间目标必须实际可达。结果可重复，并能在地图/日程发生变化后暴露差异。
6. 玩家手册说明抵达后的按键、见闻条件等待方式，并记录路线审计的基准口径；不得把未发生的外部试玩反馈写成事实。
7. 新增/更新针对性测试通过，数据校验、类型检查、全量测试和发行烟测通过。
8. 更新 `CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md` 及相关文档，记录验证命令/结果并以 `round-61: ...` 提交。

## 子任务

1. 将空间差事目标种类带入通用导航引导结果；在抵达时由 HUD 展示人物交谈、遭遇交手、见闻触发点的操作提示，并以纯逻辑测试锁定行为。
2. 将当期 NPC 与未结束遭遇作为动态寻路阻挡格，在场景刷新时重建有效路线；若障碍暂时封路则保留目标并等待状态变化后重算；测试切换日程/清除遭遇及地形永久无路行为。
3. 基于实际 100×100 地图、世界关口、R58 任务发布人/目标与七个日程时段构造可复现路线审计，核对从对应地图入口出发到目标停靠格的总步数和不可达情况；修正审计发现的不可达角色/目标资料。
4. 汇总审计口径/结果，更新玩家手册与项目文档；运行发布验证，修复回归并提交。

## 风险

- 地图导航落在人物/遭遇四邻格，不等于该 NPC/遭遇一定取得全局交互优先级；抵达文案需保持准确且不要声称目标已互动/已触发。
- 见闻目标可能受天气或时段影响；提示应建议等候条件，不能保证按时触发。
- R58 六项任务的空间目标都在发布人所在区域；区域关口路线继续由既有跨区导航回归覆盖，本表不将当前地图 HUD 的本地步数误称为跨区总步数。
- 路线距离依赖具体时段的人物位置；审计必须显式固定日程时段并在文档中说明。
- 动态阻挡可能暂时封住全部路线；引导层要区别「绕开动态占位后仍存在地形路线」与「地形本身无路」，避免前者清掉仍有效的运行期目标。
- 当前没有非维护者试玩回馈；本轮以可复现的资料路线审计代替主观试玩结论，不虚构人工反馈。
