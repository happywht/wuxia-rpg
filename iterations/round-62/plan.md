# Round 62 — 铁嶂北道第三块可玩大区

## 本轮目标

把当前两块互通的 100×100 区域扩展为三块连续可行路的江湖区域：从雾雨渡口已发现的雾岬北岸线索向北开出“铁嶂北道·岩关驿镇”。复用已核验的 Kenney 官方 CC0 Roguelike/RPG 与 Tiny Dungeon 图集，确定性生成一张有岩脊、山路、石关和驿镇聚落的 100×100 像素地图；通过明确声明的双向关口、发现点、NPC、遭遇与短任务链，让新增区域有实际探索内容。维持数据驱动地图/人物/任务/知识图谱协议，不改引擎规则或存档格式。

R62 路线图原候选为“多轮时钟推进路线模拟”。结合用户持续提出的超大可移动世界诉求以及当前仅有两张 100×100 地图的仓库实况，本轮将主题调整为第三块可玩大区；时钟/走图模拟顺延到后续迭代。

## 用户故事

- 作为已查到北岸水尺的行旅者，我希望能从雾雨渡口继续北行，手动穿过关口抵达新的岩山区域，并从另一侧实际步行返回。
- 作为探索新区域的玩家，我希望看见有辨识度的山道、石关和驿镇，能发现新地点、与当地人物互动并完成区域差事，而不是进入只有空地的地图。
- 作为内容作者，我希望地图、门口、人物、遭遇、发现事件和任务仍是可校验的独立资料，地图生成可重复，已有区域和老存档标识保持兼容。

## 验收标准

1. 新增 `map.round-62-iron-ridge`：100×100，能由固定种子的生成脚本逐字节重建；使用已登记 CC0 图集，不引入未授权素材；岩壁、石关、植被和路径由贴图层呈现，独立 `grid` 控制通行。
2. 世界舆图加入第三个区域与一组明确的双向关口；三张图的入口/落点均可走，江南道—雾雨渡口—铁嶂北道两跳行程可规划并能按玩家实际走格/按键完成往返。
3. 新图有不少于四个资料驱动地标、三处可发现事件、两名可交互 NPC、两场可重战遭遇和一条至少三段的原创区域任务链；任务与发现/人物/遭遇/奖励的引用通过现有 Schema 和语义审计。
4. 生成器将地图出生点、关口端点、事件、地标、NPC 日程点和遭遇列为受保护锚点；自动回归验证所有锚点从区域入口连通，并核对旧两图的连接与既有 R58/R61 资料不退化。
5. 更新世界舆图、世界设定、人物、任务、素材用途、玩家指南及路线图等当前文档和本轮开发日志；文档计数审计反映三张图与新增区域内容。
6. 新增专项地图/路线测试；Schema/MOD 检查、类型检查、全量测试、文档审计、生产构建与发行 smoke 通过；以 `round-62: ...` 单独提交。

## 子任务

1. 写确定性岩关地图生成器和三地图可达性回归：先保护全部玩法锚点，再生成石地/岩脊/石关/林带与行路层，并锁定可行格、边界阻挡和入口连通。
2. 装配第三地图、南北关口、四处以上地标与发现事件；给两处现有世界线索接上北行地图，验证本地图与两跳跨区导航均正确。
3. 新增两名 NPC、两场可重战遭遇、三段式差事链和知识图谱关系；核对七时段日程下无 NPC 群堵入口、任务发布人和空间目标都可抵达。
4. 更新资料作者/玩家文档及日志，执行专项与完整发布检查，修复问题并独立提交。

## 风险

- 图集瓦片拼接不当会让高地看起来像重复色块；先用原始瓦片表选择岩石/地板帧，并以实际运行画面检查路线、石关与聚落层次。
- 新地图会增加静态资源体积；优先限制贴图层数量、共享现有图集，在生成后记录压缩前地图大小和发行包变化。
- NPC 日程与地图锚点可能在某些时段堵路；按 Round 61 的真实资料路线审计方式逐时段检查入口、发布人、遭遇和事件。
- 新关口在资料层是有向边，往返必须分开声明和验证；保留旧两张地图原有关口端点与存档 id。
- 无新增素材来源，因此不下载或嵌入未核验资源；若现有 CC0 图集不足以表达关山，改用已登记瓦片重组并在范围内调整地貌设定。
