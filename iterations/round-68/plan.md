# Round 68 计划：四区长线旅程、时段变化与结局路线

## 本轮目标

把 Round 51–67 建成的可移动全域地图、四块百格区域与导航/日历/存档/结局系统放进同一条可复现的长线旅程中，检查玩家从江南道出发、跨过全部区域、经历 NPC 日程切换与存读档，再回到雾雨渡口达成一个真实结局的过程是否连贯。发现问题时修复实际运行路径或资料，而不以静态连通性断言代替旅程验证。

## 用户故事

- 作为玩家，我希望在全域舆图选择远方地点后，跨越四个区域、经历多个游戏时段时仍能找到下一座关口，且行路不被某一时段的 NPC 占位或读档打断。
- 作为完成探索的玩家，我希望在保存并恢复长途旅程后，已获得的见闻、任务状态、当前区域和游戏时间仍能继续支撑真实结局条件，并能从结局入口完成终章选择。
- 作为维护者，我希望一条测试和一份试玩记录直接使用当前基础地图、日历、NPC 日程、区域事件、存档和结局资料，让地图/日程/关口数据改变时能发现跨系统回归。

## 验收标准

1. 四张真实地图、世界地图六条有向关口、游戏日历、NPC 日程和区域事件均通过各自解析/装配；测试不为地图、关口、地点、人物、任务或结局伪造替代资料。
2. 新增可复现长线旅程回归：逐格跟随当前跨区导航，按真实步行/旅行耗时推进时钟，在时段切换后重算 NPC 占位与路线；完成江南道 → 雾雨渡口 → 铁嶂北道 → 西陲盐道探索，再经真实反向关口返回雾雨渡口结局入口。
3. 旅程中实际触发 `event.old-footprints`，在非起始地图保存、JSON 序列化/解析并恢复；断言区域、坐标、历时、已知见闻和必要任务/角色状态保留，随后继续行路并基于资料条件解锁、选择“行舟万里”。
4. 浏览器试玩覆盖扩展后的 176×112 全域舆图、缩放/平移/本区细图切换、手动走到并通过至少一个真实关口及首抵事件；浏览器中途多区域动态导航、存读档和结局不以自动化模拟冒充手动实测，改由标准引擎 API 的真实资料长旅程回归覆盖。记录操作路径、到达结果和当前验证边界。
5. 更新 Round 68 计划、试玩/旅程审计文档、`CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md` 与玩家/地图指南；定向测试、数据校验、类型检查、全量测试、文档审计及发布包 smoke 全通过，并创建唯一 `round-68:` 提交。

## 子任务

1. **真实资料长途旅程回归**：加载四张地图和全域关口，组合逐格寻路、天气步耗时、日历时段、NPC 动态占位和过图落点；验证去盐道与返渡口旅程在每次时段变化后继续推进。需要时提取最小通用测试辅助代码或修复被证实的引擎/资料问题。
2. **存档恢复与真实结局闭环**：在远区行程中走到并触发既有雨后脚印区域事件，经过实际存档协议序列化/恢复后继续行路；使用恢复出来的见闻/社会/任务状态评价现有结局条件，并从真实结局门交互规则中选择可达结局。
3. **浏览器实走、文档和发布验收**：在隔离预览实例实测全域地图/本区细图操作、缩放/平移、首个真实关口过图与到达事件；用游戏自身舆图重新规划第二段路线并记录人工试玩边界。四区往返/时段/存读档/结局由第 1、2 子任务的真实资料集成回归覆盖；更新地图/玩家指引和四项项目日志，跑完整质量门槛及包内 smoke。

## 风险

- 上轮已有逐区静态路线审计，但它不等价于跨图、跨时段、存读档的连续旅程；本轮必须在模拟器与浏览器两端分别观察，避免用单一测试覆盖支撑过宽结论。
- 近千格逐步重算路线的测试可能耗时；优先复用确定性 BFS、真实时间成本与已编译日程，必要时每一步仍重算导航但避免重复重建静态 Schema/图集。
- 盐道目标、脚印事件或结局门存在见闻/交互时序门槛；通过真实事件选择与结局引擎检验，不手动注入最终结局状态掩盖路径问题。
- 长途浏览器操作可能暴露图集、碰撞、过图入口、输入锁或浏览器自动化限制；只在隔离预览页验证，并如实记录尚未走通的段落。
- 浏览器把模拟路径人工转录成按键串可能受运行时动态占位/手动转录误差影响；优先以舆图当场重新规划并明确区分手动试玩与 Phaser-free 真实资料集成回归的证据范围。

## 预计人类工程师工时

约 90–150 分钟，包含旅程模拟/动态日程回归、真实存档往返与结局闭环、浏览器跨区试玩、如有发现则修复与复测、文档/日志更新和完整发布验证。
