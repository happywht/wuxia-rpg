# Round 69 计划：武学可获得路径与身法战斗定位

## 本轮目标

不以静态总数代替玩家可获得性，审计基础资料中的 30 门武学是否能从开局武学或真实师门授艺路径学到；根据武学类别和描述修正身法在战斗中被当作攻击技的问题，为玩家与敌方提供数据驱动的一次性守御动作，并记录各派学习覆盖与守御数值边界。

## 用户故事

- 作为玩家，我希望资料列出的门派武学确实能从对应师长处习得，需求属性、等级和门派不会把武学锁成只有名目的内容。
- 作为玩家，我希望身法招式体现避势、换步和护身，在对手下一次来袭时提供有限的伤害减免，而不是产生与招式描述冲突的直伤。
- 作为维护者，我希望更改门派、对话授艺或战斗动作资料时，测试能指出断掉的学习路线、无效师门引用及身法战斗映射错误。

## 验收标准

1. 对当前基础资料逐门核算 30 门武学：开局即得的武学有有效角色模板来源，其余武学在从对话起点可达的真实对话路径中存在同 ID 的资格条件与学习效果；门派武学须与已登记门派及有效导师/授艺对话吻合。`skill.lanmen-daofa` 保持无门派定位，并为盘舷门外玩家新增能抵达的授艺入口。测试报告出可习得数量、五派分布与未覆盖 id。
2. 武学 Schema、运行时防御解析和 MOD 覆盖验证均接受 `guard` 战斗类型；现有攻击/疗伤及自创武学协议保持有效。
3. 四门类别为「身法」的基础武学改为一次性守御：消耗按内力成本、守御值按数据读取；下一次攻击的标准伤害减去守御值且最终伤害至少为 1，结算后守御清除。敌方有可用攻击时仍优先攻击，无可用攻击时才使用可用守御，否则按既有行为蓄势。
4. 专项测试覆盖玩家/敌方守御、仅抵挡下一击、最低 1 点伤害、内力扣除、敌方攻击优先、无动作回退、坏学习引用检测及实际对话学习效果；全量数据 Schema、类型、测试、文档审计和发行 smoke 通过。
5. 更新武学目录、战斗与数据协议、测试说明、`CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md` 和 README 当前进度；验证结果记入本文件/开发日志，并以唯一 `round-69:` 提交。

## 子任务

1. **武学可获得路径与门槛审计**：从角色模板、真实 NPC/门派资料和全部基础对话收集 `learnMartialArt` 路径，逐 id 对齐 30 门武学；校验从起点可达的资格条件配对及门派导师关系，为无门派的拦门刀法补公开门外路线；补测试与可读审计表。
2. **守御动作协议与实战闭环**：扩展武学 Schema/解析器/战斗会话和战斗面板；为身法类数据配置守御值与内力成本，并让敌方在没有可用攻击时才选守御；补足一击消耗和最低伤害规则的回归测试。
3. **平衡记录、资料文档与发行验收**：更新 `docs/MARTIAL-ARTS.md` 的完整 30 招目录和授艺来源、`docs/COMBAT-BALANCE.md` 的 AI/守御规则、`docs/DATA-GUIDE.md`/架构/玩家指南、测试指南和四项轮次日志；运行定向及全量质量门槛，核对发行白名单并提交。

## 风险

- 仅在对话中出现学习效果不代表路线可用；必须把发起对话的 NPC、门派资格及人物属性/等级门槛一起核验，避免漏掉已学起始招式或误计无效导师。
- 声望和善恶有部分拜师门槛依赖易漏看的主动对话效果；本轮优先保障武学授艺路线真实可达，并在平衡审计中记录尚未改造的门槛依赖，不扩大为任务奖励协议重构。
- 守御会改变旧战斗的伤害曲线；仅让守御抵挡下一次伤害、保留至少 1 点伤害、消耗内力并使强攻击优先，可限制拖延与反复叠加，实测仍需检查现有开场遭遇和敌方行动。
- `power` 目前同时承担伤害与治疗强度；守御必须明确将该字段解释为减伤值，不能在 UI 或文档继续把它标成通用功力。
- 自创武学只产出攻击/疗伤，需要保留其受限协议；若守御类型意外进入锻造预算或旧 MOD 解析路径，应由 Schema/解析回归定位并维持明确边界。
