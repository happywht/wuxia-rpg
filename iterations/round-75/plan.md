# Round 75 计划：让大地图区域线索可被察觉

## 本轮目标

在五个可探索区域中，为固定的地图发现事件加入数据驱动的“临近线索”提示。玩家走近尚未发现的遗迹、路标或区域初见事件时，HUD 先给出简短氛围提示；走到触发格后再播放完整发现文本并登记知识。提示应服从地图事件条件与一次性状态，不把剧情文案或区域名硬编码进引擎。

## 用户故事

作为探索大地图的玩家，我希望靠近可调查地点时能察觉附近有值得留意的痕迹，同时仍需亲自走到地点才能揭开具体内容。

## 验收标准

- 地图固定事件可通过可选 `approachText` 提供临近提示；旧地图资料缺少该字段时仍可正常加载。
- 纯引擎选择逻辑只提示当前地图上、满足条件、尚未完成且知识尚未发现的事件；按曼哈顿距离选择最近者，同距离以稳定顺序决胜；不在触发格本身显示提示。
- 提示不返回或泄漏事件完整文本/知识节点，只返回数据提供的临近文案。
- HUD 只有在更直接的交互提示均不存在时显示线索提示；临近线索不能遮挡 NPC、战斗、设施或关口操作。
- 至少覆盖五个区域的固定发现事件，并有单元测试验证筛选、距离、条件、已发现状态和排序。
- 更新地图/数据说明、玩家指南、测试说明及 CHANGELOG、DEVLOG、ROADMAP；本轮验证记录在计划文件，独立提交 `round-75: ...`。

## 子任务

1. **数据与引擎规则**：扩展地图事件 schema 与解析；实现无 UI 依赖的最近临近线索选择器；为区域发现事件添加简短、原创的临近提示。
2. **探索 HUD 接线**：把线索纳入地图互动提示优先级，确保具体交互优先；增加选择器与地图事件数据测试。
3. **文档与交付**：说明字段及玩家可见行为，更新四份项目日志/路线文档，运行相关测试、发布验证与构建并记录结果，提交本轮。

## 风险

- 若临近事件与地图关口或附近 NPC 重叠，提示可能产生噪声；以明确的 HUD 优先级避免覆盖可操作对象。
- 一次性发现和旧存档状态必须沿用现有地图事件/知识图谱状态，不新增必须迁移的存档字段。
- 事件数据规模跨五张地图，需验证 JSON Schema 与默认资料校验，避免遗漏引用或无效坐标。
- 临近提示只提供探索氛围，不得提前展示事件发现文本或知识图谱内容。
