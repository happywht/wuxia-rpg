# Round 80 计划：地图环境交互协议

## 本轮目标
为地图中的告示牌、门户等环境对象建立可选、数据驱动的交互声明，支持格点定位、朝向/调查距离与条件引用；接入现有交互入口，并证明未声明该字段的旧地图和 MOD 仍按原规则运行。

## 用户故事
- 作为玩家，我走近地图中的告示牌或门户时，能看到它可调查，并按地图数据触发对应内容。
- 作为资料作者，我能在地图数据中声明环境交互对象及其数据引用，而无需修改引擎代码。
- 作为 MOD 作者，我不必立即迁移旧地图；缺少交互声明时原有 NPC、触发器和地标行为保持不变。

## 验收标准
1. `world-map` schema/解析器校验事件可选交互声明，包括提示、距离和允许接近方向；缺省交互声明时旧事件协议不变。
2. 引擎选择器只读取通用网格/交互字段；条件、已完成的一次性状态与通路阻挡不满足时不执行。
3. 至少两个真实地图事件（云岭悬桥、海岛灯标）从踏入发现改为邻近按键调查，并复用既有事件文本/知识发现结算。
4. 自动测试覆盖旧地图兼容、格点与方向/距离筛选、成功交互、条件阻断、视线阻挡及无效声明隔离。
5. 更新交互/地图数据规范、Round 80 开发记录、变更日志与路线图；运行项目校验并提交 `round-80: ...`。

## 子任务
1. 梳理地图 schema、环境对象/传送/对话交互入口与现有兼容测试，确定最小稳定字段协议。
2. 实现 schema 与通用交互解析/输入接线，并加入旧数据兼容和条件/朝向测试。
3. 将至少两个地图环境对象迁移为数据声明，检查它们与已有事件、对话及 MOD 覆盖机制的引用。
4. 更新规范及各项开发文档，运行验证；必要时对当前浏览器预览进行一次实际交互检查。

## 涉及文件

- `data/base/world/world-map.json` 中至少两个环境调查点

## 协议落点说明
梳理后确认固定区域事件已有地图坐标、条件、一次性状态和发现节点，故本轮扩展 `RegionEventData`，不另建平行地图对象集合。旧事件省略交互声明时仍按原路径踏入触发；带交互声明的事件走朝向/范围内的 E 键调查，并复用同一组条件、结算与知识发现逻辑。该调整避免重复字段和 MOD 迁移，也使本轮涉及范围以 `world-map` 契约而非 `grid-map` 碰撞协议为准。

## 风险
- 现有地图可能用 landmarks、触发器或传送点承载了重叠语义，需要优先扩展既有协议而非引入平行机制。
- 方向、调查距离和移动时机处理不一致会造成“看得到提示但无法交互”；测试需使用网格坐标覆盖边界。
- MOD 覆盖合并规则可能改变缺省字段语义，需验证缺字段时保持既有加载路径。
- 浏览器预览服务可能已退出；自动化逻辑与 schema 验证仍作为主要可重复证据。

## 预计人类工程师工时
约 45–75 分钟，包含协议梳理、实现、测试、文档和一次集成验证。
