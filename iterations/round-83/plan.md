# Round 83 计划：青帆埠港镇与可组合内容资源

## 本轮目标

把 Round 82 只有一位居民和一项差事的东溟海岸扩成可停留的港镇：玩家可买到沿岸补给、遇见随时辰活动的港民、接续潮尺旧记的沿岸差事并面对一场原创战斗。新增人物、物品、商店、遭遇、任务和对白仍按轮次拆成独立资料文件；为此修复世界装配器对人物/对白/任务可多资源加载、而物品/商店/遭遇仍按单一资源 id 读取的不一致。

## 用户故事

- 作为玩家，我在青帆埠能找到经营补给的港商，按时段遇见巡潮渔户，并通过现有 E/F、商店、任务和战斗界面完成一段新的海岸故事。
- 作为内容作者，我可在 manifest 中注册新的物品、商店和遭遇集合文件，不必把东岸资料并入 Round 06/05 的中央大文件；坏掉的一份可选资源不会关闭其他同类资源。
- 作为玩家，我能沿已规划的多区行程实走到海岸、体验港镇内容并确认返回云岭的路线。

## 验收标准

1. 本计划先于实现写入，并拆出至少两个独立可验证子任务。
2. `world-loader` 按 manifest 顺序汇总任意多个 `items-set`、`shops-set`、`battle-encounters`，保留原单资源 id 和 MOD 覆盖兼容；重复 id 仍确定性保留首条，结构损坏只跳过对应集合并给出可读诊断。
3. 新增 Round 83 独立 NPC/对白/任务/物品/商店/遭遇资料并在 manifest 接线；港商位置有时段日程、货架只引用有效商品、战斗位置可达且不与 NPC/出生点/地标冲突。
4. 新增与「潮尺旧记」衔接的原创沿岸任务链、可重复触发以免提前胜利锁任务的遭遇、沿岸发现节点与对应舆图地标；两种商店商品均可经现有交易路径装配。
5. 复用仓库已经登记的 CC0 像素图集；若增补岸边摆设，只能声明现有授权图集帧并由地图数据表达，不添加手绘占位或无出处素材。
6. 专项自动回归覆盖资源集合合并/隔离、引用与重复项、NPC 七时段日程/位置、商店购买、关口/遭遇可达性、对白接取、战斗推进、任务链与奖励见闻。
7. 更新 README、路线图、CHANGELOG、DEVLOG、数据/架构/地图/任务/人物/测试说明；运行专项与全量检查、生产构建，并在独立浏览器中尽可能实走海岸关口、交互和返程，准确记录已完成与未完成范围；独立提交 `round-83: ...`。

## 子任务

1. 阅读并锁定 `items-set`、`shops-set`、`battle-encounters` 当前单例装配点及跨资源校验，重构为按 schema 聚合可选资源；新增隔离坏资源和重复 id 的回归。
2. 为青帆埠生成独立 Round 83 物品、商店、NPC/日程、对白、遭遇、任务链和图谱节点/边；用实际 R82 地图资料检查坐标、碰撞、日程与旧关口不变。
3. 编写真实基础数据专项，串接资源加载、NPC/商店、战斗遭遇、对话/任务效果及奖励见闻；逐步扩充以旧六区为基准的固定计数测试。
4. 更新所有玩家/作者文档和 50+ 轮路线图；隔离浏览器操作本区舆图路线、港镇交易/任务及返回入口，再运行全量验证并提交。

## 风险

- 当前 `world-loader.ts` 的物品、商店、遭遇读取使用固定资源 id；多文件合并必须保持旧 MOD 同名覆盖、顺序稳定及最小单元故障隔离。
- 新 NPC 的静态点与时段点都要可通行；编译日程还须检查同区占位和遭遇格，避免某一时段失踪或压住交互目标。
- 新遭遇若不可重复，玩家先自由探索并击败它可能锁死后接任务；需由遭遇重复策略与任务测试确保不会形成不可完成任务或无节制的奖励刷取。
- 浏览器实走需要按游戏移动动画节奏操作多张百格地图；无法走完时必须把实际范围单独记清，不用自动导航断言冒充实走。
