# Round 89 计划：雾航湾航路协作与跨海图引

## 本轮目标

在十区 512×384 可移动舆图与雾航湾既有双向关口之上，增加一名有七时段日程的航路协作者、一处跨区可追踪的海岸标记，以及一条从雾航湾出发、前往东溟海岸勘验并返回复命的原创差事。舆图目标、区域事件、人物对白、任务阶段和知识图谱继续由独立资料声明，沿用已登记 CC0 像素图素，不改动既有地图像素、碰撞和旧任务进度。

## 用户故事

- 作为第一次到雾航湾的旅人，我能从航路协作者处接到清楚的跨海委托，并看到他随时段在渔村与码头之间巡行。
- 作为正在寻路的玩家，我能从差事日志导航到舆图所示的东溟海岸目标，沿已存在的步行关口实际往返，再回岛报告。
- 作为资料作者，我能用人物、地图事件、任务和图谱 JSON 描述新路线；旧 MOD、旧存档和既有区域投影保持兼容。

## 验收标准

1. 计划在实现变更之前落盘；至少三个可分别验证子任务；预计人类工程师工时不少于 10 分钟。
2. 新航路人物由独立 NPC/对白资源登记，七时段位置无碰撞、无时段冲突且从入口可达；交互不依赖引擎硬编码人物名或剧情文本。
3. 新跨区差事至少包含“接取 → 导航并发现远区航路标记 → 返回发布人复命”阶段；Q/N 导航能从任务目标解析远区目的地，且玩家仍需实际走格/过关。
4. 航路标记作为资料驱动区域事件和可见舆图目标；任务/地点/人物/事件的知识图谱端点与关系引用完整。复用已登记 CC0 资产，不引入未经授权的美术资源。
5. 专项回归以真实地图和任务运行时覆盖七时段可达性、事件和世界地图投影、任务顺序/导航、跨区关口步行路径及旧数据装配；`npm run validate:data`、`npm run typecheck`、`npm run check` 与生产构建通过。隔离浏览器从新游戏核对 512×384 全域 M 舆图正常显示；若未在浏览器实际走完长途差事，DEVLOG 明确区分地图 UI 核验和专项路线测试。
6. 更新相关世界/人物/任务/地图/图谱/导航文档、`CHANGELOG.md`、`DEVLOG.md`、`ROADMAP.md`；以 `round-89: ...` 独立提交。

## 子任务

1. 勘验雾航湾与青帆埠可达格、舆图投影及当前内容资源注册；选定航路 NPC/标记位置并锁定旧地图哈希与锚点基线。
2. 添加航路 NPC、数据对白、远区区域事件/舆图标记、跨区差事与图谱节点/边；保持所有稳定 ID 和旧任务阶段不变。
3. 扩展专项测试，验证日程、地图条件/可见目的地、远区 Q/N 导航及跨关口行走可达，并回归旧数据 MOD/装配。
4. 隔离浏览器从新游戏手动核对地图页面；跨区事件/返程由专项测试逐格回归。更新文档、跑完整门槛，检查差异并提交。

## 风险

- 雾航湾/青帆埠已有静态地标、NPC 与事件密集；新点位须用真实碰撞网格和动态日程路线检查，不能只按绘制层判断可达。
- 新远区目标若已存在相似见闻，可能与玩家旧档已发现状态交叠；使用全新稳定知识节点和事件 ID，不复用或重置旧发现。
- 任务导航只提供下一段行路提示，不自动传送、过关或替代步行；对白和提示应说明玩家仍需返回复命。
- 这轮继续使用现有 CC0 图素，不声称新增美术素材；目标是让可移动舆图上的跨海节点进入实际玩法路线。

## 预计人类工程师工时

约 12–18 小时，含跨区任务设计、NPC 日程冲突排查、图谱闭环、全量兼容回归、浏览器走查与文档整理。
